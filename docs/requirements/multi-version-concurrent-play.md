# 用户需求补充：多版本并发游玩

日期：2026-10-28。来源：用户明确要求“可以同时管理多个游戏版本，并打开游玩多个版本的游戏”。状态：已纳入后续实现，尚未开发验收。标识：USR-001。

该要求补充 GAME-004/005/006、§11 和版本/存档影响范围，明确区分多安装并存、版本切换与多个游戏进程同时游玩；不改写原始 PRD 快照。

## 必须实现

- 游戏库同时保留多个本地版本/分支安装，分别显示安装身份、版本证据、摘要和状态。
- 可为各版本建立独立游玩实例，绑定安装、存档根范围、配置及其他实际写入目录；不同实例的写入范围得到验证且不重叠时，可同时运行。
- 每个实例独立记录启动/退出、进程身份、存档/环境观测、任务与审计；不能把一个实例的退出或稳定性结论应用到另一实例。
- 同一世界、共享可写配置、嵌套/链接别名指向同一范围或未知写入范围仍须冲突；不直接删除当前全局锁来伪装支持并发。
- 扫描、备份、恢复和检查按资源范围协调；操作一个范围时，不应无理由阻塞经验证互不相关的范围。运行实例仍引用的安装/资源不得被管理器更新或清理。
- 版本/存档关联与兼容性仍独立：并发可运行不等于任意存档可跨版本加载；升级/降级风险、保护点与隔离试运行继续执行。

## 验收场景

1. 安装 A 与安装 B 使用独立、经验证的游玩范围，同时启动并显示两个真实活动实例。
2. 两实例的游戏写入分别落入各自范围；切换焦点、退出 A 不影响 B 的监测或存档判断。
3. 第三个实例尝试使用 A 的同一世界/可写配置被拒绝，解释具体冲突；路径别名不能绕过。
4. 备份或恢复只与涉及相同写入范围的实例冲突；不对无关实例套用退出/稳定结论。
5. 应用重启后对遗留实例保守标为状态未知并保留对应范围保护，不猜进程已退出；PID 复用与子进程接管需验证。
6. 未识别版本/未验证存档绑定允许继续保守导入与单实例预览，但不能据此宣布安全并发或游戏兼容。

实际游戏启动参数、配置/缓存布局及子进程行为需基于授权样本和版本适配器验证，不凭文件夹名称或用户填写的版本名推断。当前实现仍是单工作区全局冲突模型，USR-001 未完成。

## 2026-10-28 登记基础进展

已提供安装关联的独立实例登记与目录分离检查，绑定状态仍为未验证；同一安装可登记多实例。尚未改变现有启动、会话互斥或工作区备份范围，因此 USR-001 并发验收仍未完成。后续优先验证游戏适配器与实际写入范围，再接入实例启动和按范围冲突控制。见 [实现边界](../design/play-instance-registration.md)。
