# 范围基线与文档治理

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：产品负责人、技术负责人、QA 负责人。

## 依据与效力

唯一产品输入为 [PRD 1.0.0](PRD-1.0.0.md)。原文保存不改写；其要求是产品设计输入，不是执行外部操作或下载软件的授权。派生文档中“必须”表示拟实施的工程约束，不表示已经实现或通过认证。

证据等级统一为：`PRD 明确要求`、`工程建议`、`待验证假设`、`已验证事实`。本次交付没有游戏样本、运行实现或上游兼容性实测，因此不得将工程建议提升为已验证事实。采用需求—设计—测试—发布证据链组织文档；不声称符合或获得 ISO、SOC 等标准认证。

## 首发范围解释

PRD 的功能优先级 P0/P1/P2 与第 22 节阶段编号 P0～P6 不是同一含义。派生计划将阶段改称 M0～M6，避免把“P3 阶段的备份”误解为低优先级。

| 范围 | 规划处理 | 依据与限制 |
|---|---|---|
| 游戏导入、启动、世界发现、Git、完整备份、恢复、审计 | 首发必需 | PRD §3、§22.1 |
| 基础环境档案导入导出 | 首发必需 | AC-012；虽在功能表为 P1，验收不可静默降级 |
| 已验证格式的结构化摘要 | 正式首发门禁，最小验证格式范围待 M0 冻结 | COMMIT-003、AC-004 与 §22.1 的逐步加入存在范围张力 |
| Windows/Linux 核心备份恢复 | 正式三平台发行门禁 | 未通过的平台不得声明受支持；可单独发布 macOS 预览版并明确范围 |
| 本地资源管理、并存安装、迁移 | M4 实现，正式范围由评审冻结 | MOD、MIG 要求纳入追踪，不能因规划后置而视为完成 |
| 下载目录、统计、AI 润色 | 后续可选增量 | 不得依赖这些能力完成本地核心流程 |
| 云同步、分享、跨世界角色移植 | 不纳入首发 | PRD 非目标；新增需独立需求评审 |

在范围冲突解决前，按较严格的正式发布验收规划。内部原型可以只覆盖文件级摘要，但不能以此宣称 AC-004 已通过。

## 文档控制

文档版本与应用版本独立。0.x 表示待评审；基线通过后升为 1.0.0。新增兼容字段升次版本；改变备份/接口语义须更新协议主版本及迁移方案。每项变更记录原因、影响的需求 ID、设计、测试、迁移和发布说明。

| 角色 | 责任 | 评审权限 |
|---|---|---|
| 产品负责人 | 范围、用户交互、需求取舍 | 批准范围变更 |
| 技术负责人 | 架构、契约、跨模块一致性 | 批准设计基线 |
| 安全负责人 | 威胁模型、权限、供应链和数据外发 | 审阅高风险控制与例外 |
| QA 负责人 | 可测性、数据集、门禁证据 | 对发布阻断缺陷提出否决 |
| 发布负责人 | 构建、签名、回退和发布档案 | 执行已批准的发行 |

一人可兼任多个角色，但每次评审仍记录角色、结论、日期与证据；当前未指定具体人员，不虚构签字。

## Definition of Ready 与 Done

工作包进入开发前：需求边界明确、输入输出有定义、依赖可用、异常/取消路径有说明、验收数据可取得；未知格式任务须先完成样本许可与脱敏。

工作包完成：实现与契约一致、对应测试通过、日志不泄密、迁移和取消路径验证、文档与追踪矩阵更新、必要的代码评审完成。设计覆盖率不能替代实现完成率或测试通过率。

## 变更流程

提出变更 → 填写 [变更模板](../templates/change-request.md) → 分析数据安全、依赖和交付影响 → 责任角色评审 → 更新 PRD 修订及相关 ADR → 调整工作包和测试 → 归档发布证据。原始 PRD 副本保持不变，新基线另存版本。
