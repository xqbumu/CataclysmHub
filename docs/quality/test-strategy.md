# 测试策略、验收用例与发布门禁

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：QA 负责人。依据：PRD §20 及全部 AC。

## 测试分层

domain 单元测试覆盖不变量、状态转移和保留集合；Rust 集成测试覆盖真实 Git、SQLite、归档及进程；前端组件测试覆盖状态呈现与确认；端到端覆盖导入→启动→退出→快照→备份→恢复。平台原生窗口、权限、签名及文件系统行为须在相应系统实测，不能用浏览器测试替代全部桌面验证。

安全核心采用属性/模糊测试：任意归档不写出沙箱；任意损坏输入不 panic 或无限消耗；任何失败不能改变源字节。恢复以独立遍历/哈希的 oracle 校验，不只复用被测代码返回的成功值。

| 集合 | 内容 | 验证用途 |
|---|---|---|
| FX-01 | 合成单世界单角色及空目录 | 正常完整往返 |

| FX-03 | 授权脱敏的目标版本前后存档 | 真实格式解析与证据 |

fixture 清单记录来源、授权、脱敏方法、游戏精确版本、文件哈希、期望边界和已知限制。真实玩家数据未经授权不能提交仓库。当前仅有契约示例，不将其当作 CDDA 格式样本。

## 发布阻断规则

AC-001～013 全部具备明确证据，所有声明支持的平台通过核心流程；数据丢失、越界写入、静默失败、保护失败仍覆盖、不可恢复的迁移均为阻断缺陷。结构化摘要尚无目标样本证据时 AC-004 未通过，不能以模板摘要替代。

PRD 指标按 §1.1 原定义计量：备份可验证率分母排除用户主动取消与磁盘不足，但原始失败数仍报告；恢复演练发布阻断用例必须 100% 通过；自动检查点须有效快照或明确失败状态覆盖 ≥99% 可复现场景。每次报告同时列分子、分母、样本和排除项，小样本不得宣称生产可靠性。

## 缺陷分级

S0：已发生数据丢失/范围外写入/可利用执行，立即停止发行。S1：核心恢复不可用或安全门禁失效，阻断发行。S2：可规避的非核心功能故障，负责人明确决定是否接受。S3：文案/非关键视觉问题。延期须有责任人、理由和补测，不允许把安全阻断降为已知问题放行。
