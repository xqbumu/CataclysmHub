## 保留的阻断项

1. **原生窗口定位未完成。** 原生应用列表没有可选择的 Resources 本体，按本体路径和名称定位均返回 Invalid app，按 H 完整测试包定位返回 timeoutReached，没有观察到第二个测试进程。不能区分窗口激活、包封装及工具识别限制，也不能据此声称游戏没有显示窗口。需要建立可重复的窗口定位闭环，再做世界与角色操作；不得换成外部启动器后冒充 Hub 验收。
2. **带缓存的副本并非直接可玩证明。** I debug.log 有 58 次 Stale game data detected。固定源码研究文件 `research-0.I-1/src_flexbuffer_cache.cpp` 327–340 行以 JSON 修改时间与缓存记录时间是否相同判断旧数据。示例 tips.json 在来源与副本中字节相同但 mtime 不同，与复制温缓存后失效的机制一致。本轮未通过删除缓存、抑制错误或修改官方资源掩盖问题。后续需用干净发行包对照，确定明确的时间戳保留契约或适配器缓存重建流程；现有完整性校验不能替代游戏缓存兼容性。
3. **包范围保护缺口。** 代码此前把 Contents/Resources 工作目录作为安装范围，可能漏掉同 .app 中的相邻目录；本轮另行补回归与修复，见下节。该缺口不是上述窗口定位或缓存错误的已证实原因。

## 包范围保护回归

三个新增用例在修复前全部失败：可把同包 Contents/MacOS 空目录登记为实例、已有此类实例时仍可导入 Resources 本体、冲突预览只显示 Resources。修复后统一按最近的大小写不敏感 `.app` 祖先保护整个包，普通目录安装仍保持原工作目录范围。

安装导入、实例登记、实例启动/备份身份预检、资源预览与持久会话声明使用同一边界函数；复制任务复用该函数。实际 executable 和工作目录不改变，也不据后缀认定包可信。重启旧会话派生整包保护，无需数据库迁移；实例自己的目录声明不因路径包含 `.app` 而被错误扩大。

第四个回归覆盖旧库中已存在的包内实例，启动/备份均被阻止，不执行程序、不创建实例文件。全局互斥仍保持。
