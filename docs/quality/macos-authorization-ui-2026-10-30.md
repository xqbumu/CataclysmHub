# macOS 授权引导原生界面验收

日期：2026-10-30；基线 802c671；本机 macOS Apple Silicon，普通 Debug .app。

## 范围与隔离

使用 SQLite backup 创建独立 QA 元数据副本，仅在副本中省略最后成功会话，以展示此前真实 Gatekeeper 失败的卡片。原始元数据不改写；这是历史状态界面 fixture，不是重新触发系统拦截。复用已完成系统正常授权的 QA 游戏及独立空存档环境，不再次授权、移除隔离属性或运行原包脚本。已有主力/恢复实例均不启动。

## 实际界面检查

- 原生首页可展开四步正常授权说明；高级隔离属性处理默认折叠，顺序正确。
- 展开高级入口、执行只读完整范围预览，显示准确 QA 包路径、8986 项属性、属性记录路径，风险勾选默认关闭，执行按钮禁用。长路径换行，取消和关闭可见。
- 点击取消，回到首页；元数据无 installation-security 目录，installation.quarantine 操作记录为 0。
- 从 Hub 启动同一已授权环境。会话 a67c757e-1684-4c9f-a82e-2e7aea141dae，PID 14505，参数仍指向实例独立 userdir/savedir/configdir。
- 活动状态保留授权帮助、隐藏高级隔离入口、禁用本实例重复启动；资源占用仍存在。运行时说明为普通信息而非异常警报。原生截图检查步骤、按钮及换行可读。
- 用户确认游戏正常后退出；会话 exit_code 0，进程消失，首页恢复可启动，授权帮助、异常提示及资源占用区域消失。
- 主力实例 121 个文件、恢复实例 127 个文件的相对路径与 SHA-256 清单前后完全一致；游戏程序 SHA-256 未变，隔离属性保留。

只读证据见 [verification.json](evidence/macos-authorization-ui-2026-10-30/verification.json)。本轮不创建角色，也不将进入游戏或退出码 0 算作保存/读档认证。

## 发现及修复

启动中尚未必创建进程，旧提示“已检测到启动进程”不够准确。改为“当前状态仅反映启动请求或进程状态，不代表已进入游戏”，不改变后端状态、启动方案和资源保护。相关 23 项组件回归通过，Debug .app 重新打包成功。上述原生运行状态检查使用修正前提示；最终一句文案通过回归验证，未为复验文字而重复启动游戏。

两次从 shell 后台启动时，工具最初读到空白窗口；第一次激活并打开调试器后正常渲染，第二次仅点击原生窗口、按 Tab 后也正常渲染，不需要调试器或重载。最终构建空闲首页显示正确。后台启动观察可重复，但是否影响 Finder 正常启动、根因及归属尚未定位；未引入自动重载或改动 WebView 配置，不声称此现象已修复。

## 验收边界

已验证原生帮助展示、默认层级、完整范围预览与取消、真实活动状态及正常退出。系统授权本身沿用前轮成功证据，不为复验重设系统信任；本轮未执行安全属性移除。短暂 starting 状态的显示由自动回归覆盖，不冒充完整原生停留验收。跨平台、其他发行包与正式多版本并发未在此验收。
