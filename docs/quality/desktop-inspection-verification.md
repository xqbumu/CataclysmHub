# 桌面恢复目录检查验证

日期：2026-10-27；本机 macOS Apple Silicon debug 应用。范围为 schema 5、新增持久检查任务与桌面状态分离。所有数据为此前生成的合成存档/备份副本，不涉及真实玩家文件。

## 原生演练

1. 从 schema 4 合成工作区副本启动新版应用。原恢复记录预置为需要检查，容器含完整 3 文件 / 5 条目 / 55 B 载荷、历史成功报告和未完成标记；此处是界面场景 fixture，不声称该预置记录来自本轮真实强杀。
2. 在原生备份页发起“检查已恢复目录”，观察活动阶段与可取消操作，工作区其他冲突按钮禁用。
3. 检查完成后同时显示“本次文件检查通过”“原任务需要检查”和未完成标记提示。独立 SQLite/文件核对确认 result_json 保存原标记状态、原恢复终态未改写，源存档/归档/恢复容器的精确路径和内容摘要均不变。
4. 人工对测试容器内一个文件做等长篡改，再从原生界面检查；最新状态为失败/RESTORED_DATA_MISMATCH，先前通过结论不再作为当前结果展示。目标保持篡改现场，检查没有修补或覆盖；原存档/归档不变，源备份仍为 verified，原恢复仍为 recovery_required。
5. 检查开始/终态各有审计；两次检查共 4 条，结果与失败原因独立持久化。schema 4 迁移前快照仍为版本 4、quick_check 通过。
6. 更新包后重新打开原生应用，最新失败、原恢复中断及可读原因仍然保留；没有新增检查或重放文件操作，日志中的检查失败正确显示为“失败”。

原生日志发现旧的通用 failed 标签误显示“启动失败”；已改为通用“失败”，游戏会话仍保留明确的启动失败文案。回归用例修复前失败，修复后通过。
