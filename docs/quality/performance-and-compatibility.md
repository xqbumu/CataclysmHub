# 性能预算与兼容性验证计划

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：QA、平台与性能负责人。依据：PRD §18.1、§21、§23。

## 性能预算

| 指标 | 初始目标 | 测量方法 |
|---|---|---|
| 冷启动可交互 | <3 秒，后台大目录扫描另计 | 全新进程至少 20 次，记录硬件/缓存状态、P50/P95 |
| 本地元数据查询 | P95 <200 ms | 固定 DB 规模与索引，预热/冷态分别报告 |
| 静默窗口后开始评估 | <2 秒 | 记录事件时间、窗口结束、评估启动 |
| UI 响应 | 后台压缩/哈希不阻塞操作 | 输入延迟和主线程长任务，阈值 M0 校准 |
| 取消 | 到下一安全点停止，切换阶段延迟取消 | 文件/块边界、最大单文件、重命名窗口分别测量 |
| 备份/恢复吞吐、峰值 RAM、临时空间 | 待基准建立 | 同时报告未压缩字节、文件数、压缩率、耗时和磁盘类型 |

PRD 中数值是初始工程目标，未测量前不能写入宣传承诺。建议合成数据规模：100 MiB/1 GiB/10 GiB，1千/10万条目，单大文件及大量小文件；具体上限以首发资源预算决定。每组至少 5 次备份/恢复，保留原始结果，避免只报最好一次。

## 兼容性矩阵字段

记录 application_version、OS/minor、arch、filesystem、game_branch/version、adapter/parser_version、resource_name/version/hash、fixture_set、测试用例、结果、日期和证据链接。兼容性结论仅适用测试元组，不能从某个 MSXotto+ 修订推导整个系列。

| 组合 | 当前结论 | 进入 tested 的条件 |
|---|---|---|
| macOS Apple Silicon + CDDA 0.I Ito + MSXotto+ | unverified，PRD 首要目标 | 确认精确资产/资源修订并通过完整核心链路 |
| Windows x64 + 冻结游戏/资源版本 | unverified | 原生路径、进程、归档及恢复验收 |
| Linux x64 + 冻结游戏/资源版本 | unverified | 目标发行版和文件系统上的同等验收 |
| 未识别游戏版本/分支 | unverified | 允许不透明备份；解析/配置写入能力独立授权 |

## 平台边界用例

macOS 验证大小写行为、Unicode 文件名、权限、应用退出/子进程与签名；Windows 验证文件占用、保留名、长路径、盘符/UNC、大小写碰撞和重命名失败；Linux 验证非 UTF-8 路径、符号链接、权限、挂载点和文件事件丢失。所有平台执行外置盘断开、空间不足及恢复强杀。

网络文件系统、云盘同步目录、可移动介质持久化语义单独验证；未验证时不开放覆盖恢复。稳定性检查不能阻止其他同步程序写入，UI 应提示范围风险。

## 结果与优化纪律

先记录基线再优化；每次优化同时回归源完整性与取消，不用跳过哈希来换取漂亮吞吐。Git 内容寻址载荷方案须测量重复修改后的仓库增长，若无法满足预算则提出 ADR 修订，不能私自丢弃世界文件。
