## 已确认问题

### F1 · P2 · 过时模组仍可作为新世界默认模组选择

- 位置：`crates/hub-core/src/content.rs:111`，`apps/desktop/src/contentChoices.ts:13`。
- 元数据类型及解析只保留 ID、名称、依赖和版本，没有 `obsolete`。候选构建遍历全部定义，新世界默认选择器仅限制重复 ID 和已选项。
- 触发：扫描包含 `obsolete: true` 的合法 MOD_INFO，进入修改新世界默认模组；该项仍作为普通候选出现，诊断也没有对应规则。
- 游戏依据：CDDA 0.I 官方文档明确该标记用于旧存档，不能用于新世界。不能将旧世界仍需要此模组理解为新世界可以选择。
- 最小修复：保留标记；新世界候选禁用并解释原因，后端预览/发布也检查；已有世界引用继续展示，不自动删除。
- 验收：同一过时 ID 在旧世界保持可见，在新世界默认组合中无法新增；已有异常组合显示诊断。

### F2 · P2 · 页面重建后无法恢复下载进度和取消入口

- 位置：`apps/desktop/src/RemoteCatalogPanel.tsx:39-56`，`apps/desktop/src/App.tsx:672`。
- `downloading` 初始为 false，只有本组件发起下载才轮询；下载弹窗及取消按钮依赖本地 pending/downloading。顶层页面条件渲染会卸载组件，后端下载不因此取消。重新进入页面只读取目录并同步，不恢复活动传输。
- 触发：下载中通过主导航离开游戏库，再返回；后台仍可能忙，但页面没有原进度和取消按钮。内部 WorkspaceTabs 保留已访问面板，不能解决顶层页面卸载。
- 最小修复：挂载时查询已有 progress 并恢复状态，或将传输控制放到常驻层；让任务中心提供同一个下载的进度/取消入口。无需引入新任务框架。
- 验收：延迟下载跨主导航后仍显示进度，取消确实终止；完成/失败后状态恢复，不能重复发起同一活动传输。

## 功能缺口与改进项

### F3 · P2 · 新实例资源配置缺少明确的初始化路径

- 位置：`crates/hub-core/src/content_config_plan.rs:55-56`，`apps/desktop/src/ContentConfigPreviewPanel.tsx:94`。
- 新实例尚无 options.json 或 user-default-mods.json 时，界面仍允许填写修改内容，但后端只允许修改已成功读取的文件，直到预览才失败。当前拒绝推断未知版本文件格式是合理保护；缺口在界面未把下一步转成可执行引导。
- 最小修复：按每份文件状态禁用对应编辑，解释“请先启动游戏并保存相关设置，再重新读取”；已验证的特定版本若要初始化，另行使用版本模板及原子创建，不通用猜测 JSON。
- 验收：全新实例在编辑前即看到原因和下一步；初始化后重新读取可以继续；损坏文件不能被当作缺失模板覆盖。

### F4 · P2 · 历史版本获取范围不足以支持长期多版本管理

- 位置：`apps/desktop/src-tauri/src/catalog.rs:321-347`。
- 只取近期 30 项并补最新正式版，界面筛选也仅搜索这些缓存。更新不会取回第 31 项之外的旧实验版或更早稳定版。界面已经注明范围，因此这是能力缺口，不是“更新失效”或隐瞒行为。
- GitHub 官方 API 支持 page/per_page。最小修复为用户主动“加载更早版本”或按明确 tag 查询，继续保留首次尝试后仅手动更新的规则；无需后台下载全部历史。
- 验收：近期列表之外的已知旧 tag 可主动检索、下载并复用缓存；分页错误保留现有列表。

### F5 · P3 · 解压到登记的流程仍需人工传递路径

- 位置：`apps/desktop/src/RemoteCatalogPanel.tsx:337-358`。
- 已解压记录只有复制路径，没有打开目录或携带该目录进入本地登记的动作。游戏与资源合集都要求用户切页面、再次定位包根目录。文案虽解释步骤，主任务仍被打断。
- 最小修复：提供“打开目录”“导入此目录”；自动发现仅生成候选，游戏入口和合集单包仍由用户确认。不得将解压成功直接视为安装/启用成功。
- 验收：从记录进入导入时保留路径；多入口/多包要求选择；取消不会登记或启动。

## 保持的边界与建议顺序

优先 F1、F2，再 F3，之后 F4、F5。不要为此重写启动监督、任务框架或存档格式。

继续保持已有世界模组组合只读、配置发布前保护与回滚、新目录恢复、退出状态不等于存档一致性、资源部署不等于加载成功。MOD_INFO 的 version 是说明文本，不能据此推导版本兼容区间；DDA 规则也不能不经核实直接套用所有变体。

## 首批修复

F1：增加向后兼容的 obsolete 元数据字段（旧登记快照缺少字段按 false 读取；目标配置仍依据现场重新扫描）。新世界候选保留可见但禁用；手填 ID 的本地比较与后端新鲜预览均给出诊断，现有发布流程拒绝未解决诊断。旧世界引用不因过时标记被移除或单独阻断；无论是否过时，原有依赖和扫描完整性检查仍保留。

F2：页面挂载即查询传输状态，持续以不重叠的轮询恢复活动下载名称、进度和取消入口；观察到传输结束后刷新目录记录。页面重建不再依赖旧组件的 Promise；后端既有取消与缓存逻辑不变。此轮没有增加下载持久任务或跨应用重启续传。

F3：按默认模组和声音文件各自的读取状态禁用对应编辑。缺失时引导先在游戏中保存设置再重新读取；其他异常要求排查，不建议用默认模板覆盖。
