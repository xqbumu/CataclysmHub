# macOS NSWorkspace 启动实验

日期：2026-10-29。独立临时测试包；未修改 Hub 产品启动引擎、玩家存档或上游应用包。证据见 [实验目录](evidence/nsworkspace-2026-10-29/)。

## 结果

| 场景 | 观察 | 边界 |
|---|---|---|
| Foundation 接收器 | 程序执行，回调 PID 为 -1 | 回调成功不等于可追踪进程 |
| 无窗口 AppKit 原生入口 | 回调 PID 与接收器 PID 一致，收到四个目录参数和标记环境变量 | 自建程序，不代表所有游戏 |
| CDDA 原字节脚本 + AppKit 接收器 | 回调能识别接收器进程，但接收器没有收到参数 | 不能断言系统永远只能追踪脚本；脚本丢参数已复现 |
| 同一原生测试包启动两次 | 两个进程同时存在，各收到独立参数 | 未验证真实游戏并发保存 |
| I QA 原生入口副本 | 保留时间戳的副本进入主菜单，游戏内 q/Y 退出后 PID 消失 | QA plist 已调整，不能冒充原始发行包；未创建世界或验收存档绑定 |

## 副本准备与异常

第一次使用 `cp -R` 复制带有暖缓存的 QA 包，启动后出现 Aftershock、Backrooms 的 stale game data 提示。未使用忽略错误选项；仅继续一次观察，随后对核对过路径的本轮测试 PID 发送 SIGTERM。该轮失败，不算主菜单通过。

第二次从同一来源使用 `cp -Rp` 创建新副本，并使用新的实例目录。没有修改 plist、游戏或缓存内容；通过相同 NSWorkspace 配置进入主菜单。Aftershock modinfo 样本的字节摘要与大小三份相同，普通副本 mtime 改变，保留副本与来源 mtime 一致，见 verification.json。这支持缓存异常与复制后的时间戳有关，但并非穷尽所有缓存文件的因果证明。第一次进程 cwd 为 `/`；未单独验证改变 cwd 的影响。

实例 config 中产生 options、fonts、debug 等文件，仅能证明部分配置输出进入目标目录；save 为空，不证明世界保存、重载或全文件系统写入隔离。

## 退出后的系统弹窗

游戏内确认退出后，验收脚本紧接着调用窗口状态查询。工具返回 NSOSStatusErrorDomain -600 / procNotFound，用户观察到 “The application ‘game-preserved’ is not open anymore.” 系统弹窗。时间顺序支持这是验收脚本访问已退出应用造成，不能将其归为已证实的游戏崩溃。后续脚本应在退出后检查进程消失，停止查询已关闭窗口，避免触发应用重开或系统提示。

本轮只核实 PID 已消失；NSWorkspace 未提供退出码，不能记录 exit 0。该弹窗也是本次验收的缺陷，不能描述为完全无异常。

## 实施决定

保留已简化的单一启动入口与现有受控本体适配。暂不新增产品启动模式，不改写原包，不放宽并发认证。原始 H/I 脚本没有转发目录参数，直接改为系统打开会失去实例绑定。只有某一具体发行包通过参数、真实世界保存重载、生命周期及并发隔离验收后，才可考虑内部采用 NSWorkspace。

## 复验素材

目录内 Swift 为一次性实验源码：receiver.swift 是 AppKit 版本（Foundation 结果对应先前无 AppKit 的接收器，未保留源码）；driver.swift 为单包探测，pair.swift 为双进程探测，game*.swift 为 QA 启动配置。JSON 保留原始临时路径与 PID，属于本次历史证据，不可作为未来进程身份。截图保留异常、主菜单及退出确认。没有归档游戏二进制或玩家数据。
