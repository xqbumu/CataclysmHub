# 新目录恢复进程强杀矩阵

日期：2026-10-27。范围：已实现的非覆盖恢复核心与重启对账；macOS Apple Silicon 本机执行。测试使用合成原始二进制、两个载荷文件和一个空目录，不使用玩家数据。

## 方法

测试父进程准备合法备份与元数据，再启动独立 Rust 测试子进程。子进程使用实际 Hub 计划、持久任务、归档解码、文件写入、回读校验、完成标记和审计逻辑。在指定边界完成后，通过本机临时 rendezvous 文件通知父进程并停住；父进程用 Child::kill 强制终止并 wait 回收，然后两次重新打开原工作区。

边界调用与协调器全部受 `#[cfg(test)]` 控制，只存在于单元测试构建，不提供生产环境变量或 UI 故障开关。此处是实际操作系统子进程终止，不是仅手工把数据库状态改成 running，也不是原生 GUI 自动化、物理断电或拔盘测试。

## 本机结果

| 强杀边界 | 强杀时报告 / 未完成标记 | 重启后任务 | 独立载荷检查 |
|---|---|---|---|
| 未完成标记持久化后 | 无 / 有 | recovery_required | 载荷尚未建立，拒绝验证 |
| 第一个载荷文件写入并同步后 | 无 / 有 | recovery_required | 文件集合不完整，拒绝验证 |
| 全部载荷回读核对并同步后 | 无 / 有 | recovery_required | 字节通过，但流程仍未完成 |
| 成功报告持久化后、删除未完成标记前 | 有 / 有 | recovery_required | 字节通过，但未完成标记保留 |
| 删除未完成标记并同步后、DB 终态提交前 | 有 / 无 | recovery_required | 字节通过，不能据此改判原任务成功 |
| DB 终态及审计事务提交后 | 有 / 无 | succeeded | 字节通过，已提交结果保持 |

六个边界均通过：源文件精确路径与 SHA-256 不变，源归档仍可独立验证；重启和同请求重放均未改写恢复目录或另建目标；中断任务不误报成功、不自动重做、不留下阻塞工作区的假活动任务。第二次重启不重复追加中断审计。已完成任务不被再次归类为中断。

独立检查也在上述强杀产物上执行。它只核对源归档与 data/，只读报告标记是否存在，不修改文件、不移除未完成标记、不修改数据库或任务终态。由此明确区分“载荷字节完整”和“原恢复流程已成功提交”。

## 自动用例与命令

```sh
cargo test -p hub-core --lib restore_faults --locked
cargo test -p hub-core --test restore_inspection --locked
cargo test -p hub-core --locked
```

用例位于 `crates/hub-core/src/restore_faults.rs` 和 `crates/hub-core/tests/restore_inspection.rs`。完整本机套件 68 项通过，其中包括 6 个强杀边界用例与 1 个子进程入口；独立检查另覆盖等长篡改、缺失/额外文件、空目录缺失、类型变化、载荷/标记链接、损坏/缺失源归档、回执丢失及成功报告不能掩盖载荷变化。元数据目录移除后 CLI 仍可工作。

另在此前原生桌面创建的 3 文件 / 5 条目 / 55 B 恢复产物上运行 verify-restored，结果通过；检查前后源归档、恢复目录和元数据文件内容摘要均未变化。

## 未完成的验证

Linux/Windows 已有 CI 配置，但本轮未在这两平台实际运行。存储写入重排、真实断电、磁盘满/拔除、网络盘、原生桌面进程强杀矩阵及覆盖恢复 journal/回滚尚未完成。单元测试边界暂停确保可以确定强杀时点，不证明任意指令间隔都已覆盖；本矩阵不提升 best_effort，也不构成正式灾难恢复或游戏加载兼容性验收。
