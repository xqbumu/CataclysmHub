# 本地运维、诊断与灾难恢复手册

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：支持与核心服务负责人。依据：PRD §19、§10.5。

本产品以用户设备为运行环境，运维重点是路径、磁盘、任务和恢复健康。以下为拟实现流程；实际菜单和工具命令在 WP-10/17 完成后补充，不假设现有可执行程序。

当前开发预览已提供手动完整备份和独立校验工具：`cargo run -p hub-core --bin verify-backup -- /path/to/backup-id`。它只验证 v1 存档根目录归档，不打开原数据库/Git，不执行恢复或解包写入；详细已实现边界见 [完整备份实现](../design/full-backup-implementation.md)。本手册后文的目标替换、恢复向导和自动回滚仍为开发设计，不能当作现有菜单或工具调用。

## 日常健康

概览检查监控可用性、最后成功快照、最后验证备份、可用空间、离线卷、Git 健康和 recovery_required 任务。备份存在不等于近期可读；验证时间、当前卷状态与历史成功分别显示。

建议定期在新空目录恢复一个备份，比较完整清单并在兼容测试环境加载；不在唯一原世界上做演练。演练频率用户可配置，初始建议每次应用/格式重大升级后执行。

## 故障处置

| 症状 | 先做什么 | 后续动作 | 禁止事项 |
|---|---|---|---|
| 磁盘满/外置盘掉线 | 停止新写任务，保留 partial 标记 | 释放空间/重新连接，复验卷身份后重试 | 删除唯一有效备份腾空间 |
| Git 缺失或损坏 | 保留原存档与仓库 | 先独立完整备份，再检查仓库或重新建历史 | 自动重写/清理历史 |
| 监控失效 | 显示自动保护暂停 | 修复权限并全量重扫；手动备份可用性单独检查 | 继续显示“监控正常” |
| 恢复中断 | 阻止游戏启动和新写入 | 读取 journal，核对 target/staging/rollback 身份与哈希 | 根据目录名猜测并清空 |
| DB 损坏 | 进入受限模式 | 还原元数据备份或建新工作区重建索引 | 删除源文件以匹配 DB |
| 归档校验失败 | 隔离该归档，保留诊断 | 使用另一 verified 来源恢复到空目录 | 强制覆盖现有世界 |
| 目标被外部修改 | 使计划失效 | 重新扫描和预览，重新保护当前数据 | 使用旧确认重放覆盖 |

## 恢复中断处理次序

1. 保存现有 journal、任务状态和路径身份记录，不写源存档。
2. 判断当前目录对应旧内容还是新内容；任何不符预期的第三份内容单独保留。
3. 若新目标完整且符合预期，补记成功；否则从 rollback 或保护备份恢复旧状态。
4. 回滚同样失败时保留三份候选及日志，提示人工选择新空目录恢复；不得无限自动互换。
5. 最终验证后再解锁游戏启动；保留恢复来源和失败原因。

## 独立灾难恢复流程

在新工作区导入备份目录 → 验证 manifest 和全部载荷 → 检查目标为空与足够空间 → 安全解包 → 独立扫描比对路径/类型/大小/哈希 → 按环境档案重建游戏资源 → 明确兼容性后在副本启动。无 receipt 时重新计算验证并将来源信任标记 unknown；无 Git/原数据库不影响载荷恢复。

恢复目标 RPO 取决于最近成功检查点/备份时刻，不能承诺零数据损失；RTO 取决于数据量、磁盘和验证速度，按 [性能计划](../quality/performance-and-compatibility.md) 测量后声明。

## 诊断与支持

日志字段：timestamp、level、task_id、operation、phase、target_token、status、error_code、duration_ms、bytes_processed。默认不包含角色/地图内容、用户绝对路径和秘密。导出包包括应用/OS/架构、schema/adapter/Git 版本、任务阶段、脱敏错误和用户选择的配置摘要；导出前预览文件列表。

支持工单优先要求复现步骤、构建版本和脱敏诊断，不默认要求上传真实存档。确需样本时明确最小范围、用途、保存期和授权。发现数据丢失按 S0 处理并暂停受影响发行，不以重装应用作为首要建议。
