# 开发路线图与可排期工作包

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：产品、技术、QA 负责人。依据：PRD §22；阶段编号使用 M，区别于功能优先级 P。

## 排期假设与关键路径

在人员、预算、目标日期尚未提供时采用依赖驱动计划，不虚构承诺日期。下表相对规模 S/M/L 表示低/中/高复杂度，不是人日估算。M0 完成后由执行团队按真实能力估时，并单列跨平台、签名及样本获取的外部等待。

关键路径：版本/路径验证 → 工作区与任务基础 → 世界边界和冻结副本 → 独立备份 → 受保护恢复 → 故障注入 → 三平台验收与发行。Git 与摘要不能成为独立备份的必需依赖。

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| M0 风险与契约验证 | 样本、技术栈、路径/进程能力、设计评审 | 关键 ADR 和格式评审；真实样本边界有证据；待决项有负责人 |
| M1 应用骨架 | 工作区、元数据、任务、安装与启动 | 首要平台导入启动与任务重启可观测 |
| M2 世界与历史 | 世界识别、稳定性、冻结副本、Git/模板 | 世界隔离、完整提交、降级测试通过 |
| M3 独立备份与恢复 | 清单、归档、校验、保护、重启恢复 | AC-006～010 及中断恢复通过 |
| M4 资源与档案 | 本地资源、档案、迁移预览 | AC-012、MOD/MIG 对应验收通过 |
| M5 结构化摘要与正式发行 | 已验证解析器、三平台、签名与性能 | 全部 AC 和正式发布门禁通过 |
| M6 可选增强 | 下载目录、统计、AI、更多分支 | 每项独立开关和隐私/离线回归通过 |

## 建议迭代切片

第一条可演示切片只完成“导入一个现有安装→启动→看到运行/退出状态及审计”。第二条完成“确认世界范围→冻结副本→独立备份→恢复到空目录”，可先于完整历史 UI 完成。第三条完成“当前世界保护→恢复→强杀重启→回滚”。此后再扩展 Git 历史、资源、结构化摘要和多平台，避免界面完成而恢复机制未验证。

每个迭代结尾演示正常、取消、故障三条路径；迭代评审关注证据和风险收敛，不以页面数量衡量进度。

## 子任务模板与估算

工作包细化为可独立评审的 issue：用户结果、需求 ID、输入/输出契约、依赖、正常/异常/取消/重启验收、测试数据、文档更新、Owner、估算区间。使用 [工作项模板](../templates/work-item.md)。本交付只建立本地计划，未在远端创建 issue。

M0 的估算校准至少包含 1/10 GiB 合成世界、文件数量变化、Git 重复提交增长、三平台构建时长及恢复故障调试。样本量、工具版本和硬件一起记录，避免将一台机器的耗时直接用于所有环境排期。
