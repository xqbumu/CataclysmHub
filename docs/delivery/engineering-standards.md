# 工程开发与协作规范

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：技术负责人。依据：PRD §16、§18。

## 工程结构和环境

建议遵循 PRD 的 apps/desktop、crates/*、migrations、fixtures、tests 布局，目录按模块所有权建立，避免在尚无功能时生成大量空 crate。domain 保持无 IO，应用服务编排，基础设施实现接口。

M0 建立精确版本清单：Rust toolchain/MSRV、Node、包管理器、Tauri、Git 支持范围、平台编译工具与最低 OS。锁文件入库，干净环境安装后可复现构建；现阶段不提供尚不存在的 npm/cargo 项目命令。WP-02 必须补全可运行的安装、开发、测试、打包命令。

## 编码约束

Rust 使用显式错误类型和有界资源；生产关键路径不得依靠 unwrap/panic 处理输入错误。阻塞 IO/哈希/压缩不得在 UI 或异步执行器关键线程长时间运行。取消以协作式安全点实现。

TypeScript 开启严格类型检查；IPC DTO 与后端单一源生成或契约校验，禁止前后端独立漂移。UI 不持有安全策略的最终判断，不以按钮禁用作为唯一权限控制。

路径必须通过平台抽象处理，不用字符串拼接代替路径组件，不做有损 UTF-8 转换后回写。调用进程使用参数数组；所有外部文件都视作不可信输入。金额等无关业务模式不引入，架构围绕本地数据保护保持简洁。

## 版本控制与评审

建议短分支与小批量 PR，默认使用 `codex/` 前缀创建自动化工作分支。PR 描述给出具体问题、行为变化、需求 ID、数据影响、验证和未解决限制。数据删除/恢复、格式变更、迁移、权限或外发需对应领域责任角色审阅。

提交源码、锁文件、脱敏 fixture 与文档；不提交真实存档、备份归档、token、签名私钥、个人路径或大型生成物。fixture 的必要二进制单独说明许可和大小。

## 完成与质量检查

变更提交前执行适用格式、lint、类型/编译、单元/集成检查。测试围绕行为不变量，特别是源不变、目标可恢复和范围完整；避免只断言内部函数调用次数。故障修复添加能在修复前失败的回归用例。

接口、schema、错误码变更同时更新契约、示例、迁移及调用方；文档链接与需求追踪须通过一致性检查。注释解释不明显的安全原因，不复述代码。

## 分支合入与发布分离

合入不等于允许发行。发布需满足 [发布流程](release-and-cicd.md) 的证据、签名和矩阵要求；未经验证的平台保留 experimental/unverified 状态。不能为了通过 CI 跳过数据安全测试或把失败标为允许失败。
