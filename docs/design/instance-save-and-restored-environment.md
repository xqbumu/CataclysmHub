# 实例存档与恢复环境

目标：从当前游玩环境找到其存档，并将已完成恢复的实例副本登记为独立环境。复用现有目录扫描、实例登记和恢复检查，不增加数据库表、后台索引或自动迁移。

## 读取实例存档

服务端只接受实例 ID，解析登记的 data_root/save；不接受任意读取路径。持有现有 mutation 门，阻止活动/未知会话和文件任务；复用实例身份和目录隔离检查，拒绝根目录变更、链接及特殊文件。以目录能力打开 save，扫描沿用 20000 条目、32 层上限。缺少 save 返回空列表，不创建目录。

结果包含实例 ID、登记根路径与扫描报告。实例结果不写入工作区 world_candidate 或扫描历史，避免相同世界目录名混合。前端换来源时丢弃旧请求，核对响应来源；名称筛选只作用当前报告。结果仅为世界目录候选，不解析/推断角色身份或确认能读档。存在外部写入时仍是当次尽力枚举。

## 恢复为独立环境

仅接受持久化成功恢复任务 ID 和名称。服务端从任务推导 destination/data，从备份原实例推导同一游戏安装；普通工作区副本没有实例关联时不猜测游戏。复用现有实例登记检查，重新验证归档、恢复字节、未完成标记、安装摘要及目录隔离；即使恢复目录被清空也须验证，不能当普通空目录跳过。

重复登记同一已登记恢复根返回已有环境，不重命名、不重放恢复、不自动启动。新实例保持 binding_status=unverified，不继承启动偏好及自动备份策略。原环境、原存档、备份和恢复保护记录保持。游戏兼容性需由用户实际读档验收。
