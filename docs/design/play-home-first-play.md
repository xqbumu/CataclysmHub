# 游玩环境首页与首次游玩流程

日期：2026-10-30。范围：首屏、首次准备与既有启动入口；不改变存档保护后端。

## 首页

以 PlayInstance 对应的“游玩环境”为主要对象，复用 PlayInstancesPanel 的启动、方案检查及配置入口。按近期 Hub 会话排序，没有会话时按创建时间排序；引导刚创建的环境优先显示。卡片展示安装名称、版本、Hub 监测的运行状态和最近关联备份的历史文件校验状态。没有备份显示“尚无保护副本”，不使用绿色健康暗示。

数据目录、资源诊断和通用说明按需展开。少于四个环境时省略空搜索框；有筛选内容时保留搜索以便清除。没有资源占用时省略首页的空诊断区；活动占用和未知会话的处理入口保留。任务与保护副本作为次要入口。

## 首次准备

入口为获取游戏、导入已有游戏；已有安装可直接选择。阶段依次为：

1. 未配置工作区时确认数据位置。复用 WorkspaceSettings 和原 configureWorkspace/initialize 检查；推荐值可直接确认，自定义子目录按需展开。
2. 下载/解压后通过原生选择器确认真实程序，或直接选择本地可信程序/.app。复用现有导入确认框及登记检查，不执行包内脚本。
3. 输入环境名（默认安装名），用户明确确认后调用原 registerManagedInstance，在当前数据根目录创建唯一独立目录。不复制或迁移旧存档。
4. 创建完成后重新读取状态并回到首页。新环境优先显示，但不会自动启动。首次启动继续使用原适配预览与确认；已保存普通方案继续使用原新鲜后端计划启动。

引导在当前应用会话内跨主导航保持挂载，避免创建中离开再返回而重复提交；关闭引导不会撤销已经成功登记的安装/环境。创建成功但读取状态失败时保留完成状态，后续只重试只读刷新，不再次创建。应用重启后不持久恢复引导草稿，可通过已登记的安装/环境继续。

## 保留的安全边界

- 没有新增后端命令、数据库迁移或后台启动行为。
- 目录规范化、原生选择授权、重叠检查仍由现有 API 执行。
- 启动时的程序摘要、资源占用、普通方案互斥及未知会话门禁保持。
- 不改变备份/恢复、配置发布保护或原字节回滚逻辑；不因退出或卡片状态声明存档稳定、兼容或已自动保护。
- 下载、解压、导入、创建和启动仍是不同的授权动作，向导仅连接上下文，不跳过其检查。
- Settings 可与会话中保留的引导同时挂载，目录字段与表单使用独立 ID，避免标签或提交关联错误。

## 验证范围

组件回归覆盖本地导入到创建、创建前无写入、创建后不自动启动、刷新失败不重复创建、跨导航保留进度、既有普通方案在首页直接走新鲜后端启动计划。浏览器视觉检查使用空态和合成只读数据；不代表真实游戏、原生文件选择器或玩家数据的端到端验收。
