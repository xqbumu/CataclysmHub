# 桌面持久安装复制

日期：2026-10-28。基于独立复制格式，桌面采用“预览 → 明确确认 → 持久任务 → 独立核验 → 显式登记”流程。

## 范围与授权

来源为已登记安装，来源根和目标父目录均须经原生目录选择器授权。预览读取完整清单、程序摘要、字节数与条目数，不创建目标。已知 macOS 程序位于 `.app` 内时，可选择包含该包的目录，实际范围收窄到完整包；选择包内较小目录拒绝。其他布局仍须人工明确完整根，不能据此推断任意游戏布局。

计划持有目录能力与原确认清单，最多缓存 8 份、10 分钟失效。确认带计划摘要、UUID 请求键和明确确认位；相同请求键按持久摘要幂等，不接受改变请求内容的重试。目标为父目录下新生成的 `installation-copy-{plan_id}`，禁止覆盖。

来源不能与元数据、工作区或实例范围重叠；目标父目录不能位于这些范围或现有安装内。启动前重新检查程序 SHA 和路径身份。任务在创建目标前将意图和审计写入同一事务。来源读、目标写占用接入现有全局互斥，未知游戏会话同样阻止复制。

## 生命周期与取消

状态为 `running / cancelling / succeeded / failed / cancelled / recovery_required`。阶段展示复制、复核来源、回读副本、提交及独立核验，条目进度不是完整性证明。快速完成任务也在终态事务记录最终条目数。

取消先持久化取消意图和审计，再通知工作者。工作者在条目及摘要循环检查取消；提交副本时与取消共用 mutation gate，发布完成后返回 `COPY_COMMITTING`，不能将已发布副本误记为已取消。取消或失败留下的目录不会自动删除或继续复制。

最终成功须通过新的独立校验，并匹配已确认的 copy ID、payload 根、清单 SHA 和程序 SHA。终态及审计一起提交。结果写入失败使用现有任务恢复覆盖层，工作者停止后释放运行占用；用户可重试记录结果，然后重新核验。

重启把遗留 running/cancelling 标记为 recovery_required/interrupted，不重放任务，不自动导入，不清理目录。完整副本可显式核验登记，但中断历史仍保留。

## 登记事务

登记重新读取全部副本，核对数据库中原始确认摘要，并检查容器和 payload 根身份、程序摘要。新增安装、导入审计、任务关联和登记审计在同一事务提交；任务关联未实际更新也回滚新增安装。同名重复请求幂等，不允许隐式改名。

登记不修改已有实例关联、游戏参数或存档，不把版本、绑定、签名、隔离标为已验证。副本中的绝对配置路径、ACL/xattr、代码签名及真实游戏写入范围仍需后续适配与验收。全局互斥保持开启。

审查修正：安装导入、实例登记也遵守当前全局资源互斥，不能在复制 payload 已出现但任务仍活动时抢先登记其子目录或程序。副本校验的容器控制目录限 3 项、payload 父目录限 1 项，遇额外项立即拒绝，不无界枚举。
