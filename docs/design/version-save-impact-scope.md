# 游戏版本管理与存档影响：范围及落地顺序

日期：2026-10-28。来源：用户要求按保留预览→后端保护→安全删除推进，同时确认游戏版本管理与存档影响必须纳入特性。原始 PRD 不变，本文件补充实施边界和依赖。

目前新备份内 game/profile_id 为 null，world_contexts 为空。这是未知事实的保留，不应根据用户写的“0.I”名称或“升级前”备注回填为已验证环境。

## 必须建设的版本与存档能力

1. **安装身份与证据。** 安装 ID、分支、版本字符串、可执行文件摘要、平台/二进制架构、来源和识别证据分开记录；用户声明、适配器观测、上游声明与实际测试不能混为一谈。优先使用有证据的只读本地检测，不为猜版本直接执行任意程序。自动下载不是版本身份管理的前置依赖。
2. **存档环境关联。** 对经验证的世界边界记录最后观测安装、版本、资源/档案摘要及时间；范围未知时按整个存档根目录保守记录，并明确绑定未验证。仅选择了一个启动路径不证明游戏实际使用该存档目录。
3. **影响预览。** 比较源/目标分支、版本、资源/配置及已知格式差异，列出受影响世界/根范围、已知冲突和未知项。任意版本字符串不同不等于可排序的升级/降级；跨分支或无法证实版本关系时只标差异/未知，不猜兼容结论。
4. **保护与隔离试运行。** 受控更新/切换前提供明确的保护点，选择保护而创建/验证失败时停止更新；保留原安装与原数据。新版本首次加载在隔离副本中验证，防止可能的存档自动迁移/重写直接影响唯一原件。文件回读通过不等于游戏加载通过。
5. **影响观测。** 先记录文件新增/修改/移除与内容摘要；语义变化只对有版本证据的适配器提供。未知格式不推断角色或世界状态，更不保证降级后可读。

兼容状态继续使用 tested / upstream_declared / inferred / unverified / incompatible，并绑定确切游戏/平台/资源组合及证据。相同版本字符串或相同可执行文件都不能独自证明存档兼容。

## 与保留、安全清理的关系

只读保留预览可以先做，不要求假造版本关联。目前预览 version_context=unverified、deletion_available=false：它模拟元数据规则，不能确定任何旧版本专属回滚点，更不授权删除。

进入危险清理之前必须增加真实介质复检、引用与环境保护判定：显式升级前保护备份、迁移测试源、仍被存档/档案引用的旧安装，以及已知环境的有效回退点。不能只保留全局最新备份，就删除某个旧版本唯一的恢复来源；未知关联不能当成“没有引用”。

命名/锁定已是保留标记，但名称“升级前”不是结构化升级事件或已验证版本关联。后续需要明确的保护目的/引用以及预期安装身份。best_effort、静默检查、文件完整性和游戏加载兼容性分别记录，不能用新版本尽力快照静默替代旧环境已验证的保护点。

## 开发顺序与验收门

1. **保留规则只读预览**：按元数据计算集合，解释命名/锁定/引用/历史校验保底，明确版本未知；不读介质、不删文件。本轮已落地初版。
2. **后端保护检查 + 最小版本/存档关联基础**：补安装识别证据、存档绑定/环境引用和升级前保护引用。清理前重新验证介质与保底，信息不明时不开放危险执行。
3. **可恢复隔离与安全删除流程**：绑定预览修订、引用和现场验证结果，先完成中断恢复证明。原版安装/存档仍被引用时不清理，旧版本回退点不能被新环境误替代。
4. **受保护覆盖恢复与版本切换**：保护副本、替换 journal、回滚及首次加载差异提示齐备后开放；完整资源档案继续按 WP-12/13 扩展，非破坏迁移按 WP-14。

版本管理不是放到可选 AI/下载阶段才补的显示功能；完整下载目录可后置，但版本身份、引用与存档影响约束必须早于受控升级、危险清理和覆盖恢复执行。没有真实授权样本/适配器证据时保留 unknown/unverified，不据此宣称某个 CDDA 版本或跨版本加载已支持。

## 用户补充：同时运行多个游戏版本（2026-10-28）

用户明确要求不仅能管理多个版本，还能同时打开并游玩多个版本。原 GAME-004 的“并存安装”不等于该并发能力，新增范围记为 USR-001，见 [需求补充](../requirements/multi-version-concurrent-play.md)。

当前全工作区互斥仍会阻止多个游戏并行，这一限制没有在本轮放开。下一阶段的最小版本/存档关联基础须包含独立游玩实例和按范围锁：每个实例绑定安装身份、存档、配置及其他写入范围；只在适配器与实例隔离得到验证后允许互不重叠的实例并发。共享同一世界/可写配置或范围未知时仍冲突，不能仅根据两个可执行文件路径不同就认为安全。

实例退出、稳定性检查、备份与审计均按实例/存档范围处理；一个版本退出不代表另一个已退出。旧安装仍被运行实例、世界或档案引用时不能更新/清理。游戏可能写入的配置、缓存等也须纳入写入范围，不能只比较 save 目录文本。新版本首次试加载继续使用隔离副本，不把并发游玩作为原件升级迁移的隐式许可。
