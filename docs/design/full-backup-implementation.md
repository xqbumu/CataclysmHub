# 完整备份与独立校验实现说明

日期：2026-10-27 · 版本：开发预览 v1 · 责任模块：hub-core/backup、backup_format。

## 已开放范围

只开放整个工作区存档根目录的完整备份。这样即使没有游戏适配器，也能完整纳入共享和未知普通文件，而不伪造已确认的世界边界。源目录与备份、应用元数据目录的分离关系在预览和执行时重新检查。

每个新备份使用 consistency=best_effort，UI 要求独立风险勾选与明确确认。不在管理器已知运行或状态未知的会话期间开始；外部进程和游戏格式仍未验证，不能升级为 quiescent_checked 或宣称可加载。

## 计划与执行

prepare_backup 在后台枚举范围，只预览路径、类型、数量和大小，不提前冻结内容。计划 ID、摘要和完整范围保存在进程内，有效期十分钟；应用重启失效。确认绑定计划 ID 与摘要，源路径集合/类型/大小变化后拒绝执行。相同长度的内容变化不属于范围预览承诺，最终以执行时复制的原始字节及源比对为准。

create_backup 使用持久 UUID request_key 和请求摘要保证重放不重复写入；同键不同请求返回 REQUEST_CONFLICT。活动扫描、游戏启动和备份/校验采用工作区级保守互斥，非通用多资源锁。

执行顺序：

1. 检查目录、范围与空间，预估冻结副本加最坏归档与头部余量；写入中仍处理磁盘不足。
2. 在备份卷创建 `.partial-{task_id}`，写 owner.json 归属标记，Unix 上限制目录访问权限。
3. 将普通文件复制到任务目录的 data/，保留空目录。源读取通过能力目录句柄和逐路径组件不跟随链接的打开方式，复制使用新文件而非覆盖。
4. 每个文件流式计算 SHA-256，检查读前读后大小与修改时间。再逐文件重新读取源并比较 SHA-256，最后重新枚举集合与大小。
5. 只从冻结副本写归档，内置 manifest.json 与 data/ 载荷，TAR 使用受控类型/元数据、Zstandard 使用校验和。TAR API 需完成归档并结束编码器，参见 [tar Builder](https://docs.rs/tar/0.4.46/tar/struct.Builder.html)。
6. 写外部 receipt，独立回读解码并核对全部清单与哈希，通过后删除任务自有的冗余冻结副本。
7. 在取消/发布互斥门内，把同卷临时目录重命名为最终 UUID 目录，移除归属标记，持久化索引、任务和审计。正式目录仅保留归档和回执。

两次源读取一致仍不是游戏事务或 OS 原子快照证明。更晚的外部写入不会改变冻结载荷，因此 UI 始终保留 best_effort。

## 取消、中断与失败

复制、源比对、归档输入和校验在数据块边界检查取消。发布与取消通过服务 mutation 门串行化，取消先到则不发布；任务已完成时取消返回真实终态，不伪称已取消。

失败/取消保留未发布目录及任务记录，暂未提供自动垃圾回收。重启把遗留活动备份任务标记 recovery_required，不盲目重放。若目录切换后元数据写入或持久化确认失败，正式载荷可能存在但尚未登记；必须保留目录并独立校验，当前没有自动孤立归档重建索引入口。

SQLite 与目录发布不构成一个原子事务。schema 3 只新增 backup_task、backup_archive，旧 schema 1/2 迁移前创建校验过的元数据备份，迁移事务失败保留旧版本。

## 清单与完整性

生成物遵循 [v1 文件契约](../contracts/file-formats.md)：内部清单记录 UUID、相对路径、类型、大小、SHA-256、格式/压缩/工具版本、best_effort 及未知环境信息。world_id 为 null，world_contexts 为空，不把目录候选 ID 冒充真实世界。当前不保存 mtime，但读取器接受 v1 契约的可选合法 mtime 字段。

外部 receipt 保存归档与内部清单原始字节的 SHA-256，避免摘要自引用。应用内重新校验时额外比较已登记的归档/清单摘要；校验失败更新记录，不依赖回执的自述成功。

独立 verify-backup 工具不打开应用数据库或 Git。回执不存在时仍读取内部清单并逐文件验证，返回 receipt_present=false；存在但损坏的回执不静默忽略。此工具验证完整性，不认证来源或宣称兼容，也不向任何目标解包。

读取器使用有界清单/数据流和解码窗口，校验精确集合、类型、大小和哈希；拒绝绝对/驱动器/穿越/反斜杠路径、重复条目、文件目录前缀冲突、额外/缺失文件、链接、PAX/稀疏等未支持 TAR 类型。支持有界 GNU 长文件名，结束后继续读解码器以检查 Zstandard 结束和 TAR 后非零内容，不仅依赖外层哈希。

## 限制与后续验收

上限：20,000 条目、32 层目录、64 GiB 普通文件总量、8 MiB 内部清单、128 MiB 解码窗口。预览元数据另有更小预算以留出文件哈希空间。读写与取消不能强制中断阻塞的 OS 调用；网络盘、介质断开、真实断电及三平台恢复仍需验证。

链接/特殊文件不支持；Unix 检测到硬链接源文件会中止，不静默扁平化其语义。只保护普通文件字节与空目录，不承诺 ACL、扩展属性、稀疏布局或全部权限元数据。源目录路径碰撞、跨平台名称映射与世界恢复语义将在恢复预检阶段继续收紧。

WP-09 的创建与校验核心已落地，但磁盘故障矩阵、介质验证和正式 AC-006 验收仍待完成。WP-10 已新增[独立新目录恢复核心](new-directory-restore-implementation.md)，桌面恢复流程、保护备份、替换 journal 与回滚尚未开放，不能把本切片宣称为完整备份恢复产品。
