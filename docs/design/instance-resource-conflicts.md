# 实例物理目录冲突预检

状态：已实现只读预检与启动检查接入；全局互斥继续保留。schema 8 不变。

## 检查范围

用户可在游戏库点击“检查〈实例名〉资源冲突”，无需选择试运行参数方案，也不因已有活动操作而禁用该按钮。服务端仅接收已登记实例 ID，由记录构造安装工作目录与实例数据根两个可能写入范围，调用者不能提交任意路径、读写模式或验证状态。安装工作目录包括已知可能生成共享缓存的 base/data 等包内位置；这一声明不代表完整的游戏写入边界。

服务端在 mutation 门内读取当前活动占用及已结束 worker 的恢复覆盖，在阻塞工作线程中对现有目录进行只读检查。canonicalize 解析别名，same-file 句柄比较物理身份并双向检查祖先；同目录、父子嵌套和符号链接别名不能依靠字符串不同躲过冲突。读/读不构成目录读写冲突，任一方可能写入则重叠即冲突。当前实例请求的两个目录均按可能写入处理；两个请求目录自身重叠也单列问题。

未知全局占用无论目录是否分离都保持冲突。目录缺失、非目录、权限/身份比较失败、声明格式未知均不能返回“可用”结论。恢复尚未创建的目标目录可能被报告为范围无法核实，仍保守阻止；当前不以最近存在的祖先推断未来目录身份。活动声明超过 10000 条或请求范围超过 1000 条直接报错，不返回截断的无冲突结果。空请求直接拒绝；请求访问模式只接受 read/write，未知模式即使没有活动占用也不能通过执行检查。

## 输出与执行边界

`InstanceResourcePreview` 包含 instance_id、checked_at、scopes、scope_issues、conflicts、binding_verified、concurrency_available。每项冲突带占用者种类/ID、操作、状态、原因及可空请求/受保护路径。全局保护和目录重叠可分别列出，同一占用者可能产生多项原因。前端显示完整数量、最多 50 项明细，并提示未显示的冲突同样保护资源。

binding_verified 和 concurrency_available 由服务端恒置 false。无活动占用不等于绑定已验证；目录问题存在时明确不能据此判断可启动。关闭对话框不改变会话/任务，不解除占用，不产生审计、租约、启动计划或文件写入。每次点击重新读取，不把前一次观察当作授权。

实例试运行生成计划时使用同一检查；确认执行仍保留原全局准入、程序摘要、方案/目录身份重验，并再次检查实例资源。旧预检结果不会被调用者提交用于跳过检查。目录比较只在观测时有效，没有取得操作系统锁、冻结目录树或持续持有租约；外部进程仍可能改变目录。完整隔离由后续适配器证据、写入范围约束和执行期保护实现。

本切片不开放按范围并发、实例备份、危险删除或覆盖恢复。相关上游证据与真实验收门继续沿用 [真实游戏绑定验收](../quality/real-game-binding-acceptance.md)。

## 准入回归补充（2026-10-28）

范围报告到执行错误的转换集中在同一个判定函数，覆盖读读放行、读写/写读/写写拒绝、独立目录通过和未知全局会话拒绝。它只判断范围冲突，不授予游戏适配方案并发资格。

另有真实子进程的合成集成测试：先为同一实例生成两个计划，同时确认，要求只创建一个会话、只启动一次程序，另一请求返回 GAME_RUNNING_OR_UNKNOWN；实际进程结束后新预览可用。子进程用显式释放文件保持活动，避免依赖短暂运行时间制造冲突窗口。这验证现有 mutation 门与执行复检，不能替代真实游戏双开或多个所有者独立退出的验收。
