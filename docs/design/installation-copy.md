# 独立安装副本：复制、边界与校验

状态：已实现核心、独立命令行及桌面持久复制任务；数据库 schema 10。桌面支持独立核验后显式登记，仍不自动绑定或启动，不开放并发。桌面任务边界见 [持久复制设计](managed-installation-copy.md)。

## 操作入口

```sh
cargo run -p hub-core --bin copy-installation -- \
  /path/to/Game.app Contents/Resources/cataclysm-tiles /path/to/new-container --preview

cargo run -p hub-core --bin copy-installation -- \
  /path/to/Game.app Contents/Resources/cataclysm-tiles /path/to/new-container --confirm-new-directory

cargo run -p hub-core --bin copy-installation -- --verify /path/to/new-container
```

预览只读取完整目录范围、每个普通文件摘要、权限及内部链接，目标不会创建。确认命令重新取得源范围，不接受预览 JSON 作为执行授权，也不声称跨两次 CLI 调用冻结了源。复制不执行任何游戏或探测命令，不打开 Hub 数据库，不修改安装/实例记录。成功副本中的程序可随后通过现有原生选择器手工导入；手工导入仍按既有规则核对程序，不自动信任复制回执或提升未验证状态。当前不提供“复制完成即绑定/启动”的旁路。

CLI 是独立文件工具，尚未参与 Hub 的持久任务及全局调度。应在游戏关闭后对明确安装根运行；两轮源检查只能提供观察到的字节一致性，不证明游戏静默、所有时间点一致或完整写入隔离。桌面现有全局保护不因副本出现而解除。

## 来源与目标

调用者明确指定完整源目录、源内普通可执行文件相对路径及新的目标容器。源根名称保持不变，副本位于 `new-container/payload/<源目录名>/`，因此 `.app/Contents/Resources` 以及同级其他完整包内容均保留。选择较小的目录不会自动推断或补全上级包；工具不宣称已识别任意游戏完整边界。

源、目标父目录均规范化并持有目录能力句柄，物理祖先比较拒绝目标位于源内，包括父目录别名。已有目标一律拒绝，包含空目录、文件和链接；不覆盖、合并、清空或自动续跑。容器在 Unix 下创建为 0700。实际复制及相对路径访问使用 cap-std/cap-fs-ext；原目录仅用于读取。

预算为最多 20000 个条目、32 层目录、64 GiB 普通文件数据、8 MiB 元数据；清单条目序列先限制为元数据预算的一半。预检不完整或空间不足均中止，不能返回截断的“完整副本”。路径采用相对、UTF-8、无控制字符/点分量的受限表示。

## 普通文件、链接与权限

普通文件以 create_new 和逐字节写入复制，不调用硬链接、reflink 或覆盖式通用复制。复制流计算 SHA-256，对照预检文件大小及摘要；源复制后全树再读，目标全树独立回读，文件集合、类型、大小、摘要、权限及链接声明均须一致。复制期间还对源/目标实际目录身份复核。新文件物理身份必须不同于源；Unix 独立校验要求每个普通目标文件 nlink=1，后续添加硬链接会使验证失败。

macOS framework 的相对链接可保留原链接文本，但必须能在源根能力范围内完整解析到普通文件或目录。绝对、越界、悬空、循环及特殊文件目标均拒绝，不解引用后静默改成普通文件。先复制所有普通目录/文件，再创建链接，最后全树复核目标链接；不会把外部链接读到的字节复制进来。Windows 链接创建可能需要系统支持或权限，失败保留未完成状态，不提权、不静默解引用。

Unix 记录并保留 0777 范围内模式位，拒绝 setuid/setgid/sticky。Windows 使用 readonly 属性，不承诺 Unix 模式跨平台映射。目录权限最后应用，避免源只读目录妨碍初次写入；写文件及权限后同步，Unix 完成前同步目录。

不保留 ACL、扩展属性、所有者或全部平台元数据，不重新签名，不绕过平台校验。字节、模式及链接一致不等于代码签名有效、LaunchServices 可启动或官方来源已认证。Info.plist 中的包标识、启动器和环境声明也不会被改写，不能用默认系统启动行为推断实例隔离。配置中的绝对路径也不会被重写；独立玩家数据、HOME、临时目录及动态库环境仍须另行验证。

## 完成协议与独立校验

容器先写并同步 `INSTALLATION_COPY_INCOMPLETE.json`。失败/取消/强杀可能留下部分 payload，绝不自动删除；标记存在时独立验证拒绝，即使文件看起来完整。复制/源复核/目标回读全部通过后，以 create_new 写入 `copy-manifest.json` 和 `copy-verification.json` 并同步，再去掉未完成标记并同步父目录。Unix 进程中断边界已测试；Windows 持久性未实机验收，掉电原子性不作为保证。

清单 v1 保存不含本机绝对路径的复制 ID、payload 根、可执行文件相对路径/摘要、根权限及完整条目。回执绑定清单摘要、文件/链接数、字节量和程序摘要；binding_verified/isolation_verified 恒 false。独立校验无需源目录、Hub 元数据或 Git；只读核对控制文件、完整目标范围与当前内容，拒绝额外控制/同级 payload、不完整标记、未知版本、被篡改回执或验证状态提升。

清单/回执没有真实性签名，摘要不是官方发布认证。独立校验给出新的观察时间，不依据旧时间或旧成功回执跳过读取。它也不持续锁住目录，外部写入仍可使结果过期。
