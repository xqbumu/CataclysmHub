# 保留规则只读预览

日期：2026-10-28。WP-11 的元数据预览初版，schema 保持 6；不包含删除、隔离移动、介质复检或持久策略设置。

## 范围与规则

当前对象是本工作区全部已登记的手动 save_root 备份，不是自动检查点策略，也不依赖 dashboard 最近 100 条的展示截断。最多完整处理 5000 条，超过预算明确失败，不给出截断候选。未登记的目录/归档不读取、不扫描、不纳入清理判断。

preview_retention 输入 keep_recent / daily_days / weekly_weeks，默认界面 7 / 14 / 8；0 停用对应规则，上限分别为 1000 / 366 / 104。仅本次模拟，不保存为设置。日窗口按生成时的 UTC 日期（含今天）计数，周窗口按 UTC 周一划分（含本周），尚未实现本地/IANA 时区设置。

规则取并集：命名、保留锁、任意恢复记录引用、非 verified 的历史状态、未来日期、最近份数、最近一个非未来的历史 verified、最近一个历史 verified/quiescent_checked，以及日/周窗口内每桶最新的历史 verified。未来记录不占最近份数或替代历史校验锚点；异常日期/容量使整个报告失败，不静默遗漏条目。日期按 RFC3339 解析后的真实时刻排序，不按字符串偏移排序；并列按 ID 确定顺序。

被任一规则命中的记录显示保留原因，其他记录为“规则外候选”。候选总容量只是清单元数据中的逻辑原始字节数之和，不是归档压缩文件大小、实际可释放空间或删除批准。

## 版本与有效性边界

报告固定 version_context=unverified / deletion_available=false，列出版本/存档关联缺失及历史校验仅为缓存的风险。当前历史 verified 只是政策模拟输入，不代表介质在线、源归档现在完整或可在特定游戏版本加载；离线/损坏条目不能在执行阶段充当真实有效保底。

后续必须补旧版本专属回退点、升级前保护事件、环境/世界引用及介质复检后才能开放危险清理。版本身份和存档影响范围见 [版本与存档影响](version-save-impact-scope.md)。本预览不能作为删除授权，当前没有删除命令或按钮。

## 实现与展示

同一只读数据库事务读取工作区和完整元数据范围，恢复引用按分组集合联接，避免对每个备份重复扫描全部历史。纯规则计算不访问存档或备份介质，不修改元数据、不写审计、不更改标注，也不创建文件任务。快照生成后可能变旧，修改参数/标注或新增备份后应重新生成。

结果包括生成时间、UTC、对象范围、实际规则、逐项原因、元数据修订、历史校验/一致性状态、保留/候选数量、逻辑字节和风险提示。Rust DTO 单一源导出 TS。界面每页 50 条，只分页展示，计算范围不因页面截断；新请求开始时清空旧结果，失败不继续冒充新结果。

初版只是有界数据库读取和元数据计算，不做长时间归档验证，因此未提供独立持久任务/取消。后续介质级预检需使用持久任务和块边界取消，不能塞入这个短命令并冒充快速预览。

## 验证

纯规则用例覆盖命名/锁/引用/保底并集、规则关闭、日/周跨年边界、未来日期、不确定状态、静默历史锚点、偏移时间排序和无效输入。集成用例覆盖 111 条完整范围（超过 dashboard 100 条）、5001 条明确失败、非法日期不静默省略，以及无数据库/原文件/审计变更。界面覆盖规则参数、原因、版本未知风险及无删除入口。

这不等于完成 BACKUP-009～011：自动检查点分类、持久策略/IANA 时区、当前有效副本复检、版本/档案保护引用、隔离/删除和恢复 journal 尚未实现。
