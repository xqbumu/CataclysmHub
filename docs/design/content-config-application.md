# 单文件配置应用与中断核对

日期：2026-10-29。状态：单文件应用已实现；原地自动回滚、多文件事务和游戏加载兼容验证未实现。

## 准备范围

由用户在已生成的配置草稿中选择同实例保护备份，明确请求准备应用。一次仅接受一个有实际差异的现有配置文件：`config/options.json` 或 `config/user-default-mods.json`。默认模组与声音配置同时变化时拒绝；两个声音字段同属 options，可在同一文件内共同变更。已有世界 `save/*/mods.json` 不受理。

重新读取草稿、校验实例安装身份、检查全部 Hub 会话和文件任务已结束。候选资源范围不完整或超限仍拒绝准备。仅调整声音时，拟应用诊断限于声音包，未变更的模组诊断仍在原始报告展示；仅切换声音开关也检查已声明且保留的声音包引用，缺失或重复候选仍拒绝。模组草稿继续采用全部候选诊断的保守规则，不推断缺省依赖语义。完整候选包列表与扫描状态仍保留并在发布前复核。候选扫描仅验证默认范围中的元数据，不验证整包内容或实际加载规则。

保护归档必须登记于当前工作区、属于同一实例及来源根。使用既有完整归档解析器核对归档／清单摘要、归档 ID、实例来源 token 和目标配置原字节摘要。配置必须与归档中的该文件相同，不能使用只是“曾经成功”的备份状态。准备保留配置根、实例根、备份根、归档目录及原文件身份句柄，计划最多保留 10 个，10 分钟过期。

计划显示目标、备份 ID、原／新摘要和拟生成 JSON，用户另行确认才能执行。应用不是只读报告的隐式动作；本轮未对用户正在游玩的游戏执行任何应用。

## 持久化与单文件发布

schema 13 新增 `config_change`：请求键和摘要、实例、备份、目标路径、原／新 SHA-256、状态及错误。只持久化操作证据，不保存可自动重放的写入程序或配置内容。原配置字节仍位于独立保护归档中。

确认阶段再次检查资源占用、当前工作区备份位置和实例身份；意图记录与审计同事务提交，任一失败或被忽略均不启动文件 I/O。相同请求键仅返回既有记录，不重复执行；不同计划不能复用请求键。

独立后台执行持有 mutation 门：重新验证保护归档，重新扫描并核对候选范围／元数据摘要，然后复核原文件身份和字节。拒绝链接、特殊文件、Unix 多硬链接、超过 1 MiB 的配置。将拟生成内容写入同目录唯一临时文件，保留普通权限、sync、回读核对摘要，再复核目标原字节与目录身份，通过同目录 rename 发布一个文件，sync 目录并回读目标及身份。只保证本次单文件发布，不将两个文件更新称为原子事务。JSON 的空白与键顺序可能归一化，未知字段的解析值保留；ACL、扩展属性和全部元数据不保证保留。

已知 Hub 会话与任务被互斥保护；无法阻止用户另行启动的外部程序。字节与身份复查和 rename 之间不是跨进程 compare-and-swap，因此必须先停止外部写入者。本功能不证明未来文件状态、游戏加载或跨版本兼容。

## 异常状态与恢复

状态为 `applying`、`applied`、`recovery_required`、`resolved_original`、`resolved_proposed`。

- `applying` 与 `recovery_required` 始终保留全局文件任务保护，直到明确核对解除。
- 发布或验证失败进入 `recovery_required`；终态／审计记录失败则保留原 `applying` 意图。界面将 applying 描述为“执行中或结果待记录”，不会直接显示成功。
- 重启仅把未完成意图标为 `recovery_required`，不恢复后台写入、不重放 I/O。忽略或失败的结果事务不会解除保护。
- 用户可从实例页单独读取历史并核对当前文件；无需重新生成草稿或准备新任务。比较当前摘要与记录的原／新摘要，检查本身只读。
- 当前文件匹配原字节或拟应用字节时，用户可明确确认保留当前配置并解除该记录的中断保护。确认阶段再次读取并匹配刚显示的摘要；运行中的后台执行不能被此入口解除。记录为 `resolved_original`／`resolved_proposed`，不冒充原操作成功。
- 文件为第三种内容、不可读、路径异常或确认前变化时拒绝解除，须先人工检查。不会自动覆盖第三方修改。

关闭界面不会取消已提交应用。异常可能留下 `.hub-config-<id>.tmp` 文件；本轮不自动删除或重用它。已增加[明确确认的原字节回滚](content-config-rollback.md)，中断记录须先完成只读核对；不自动覆盖第三种内容。独立备份恢复仍只恢复到新目录，不能把“备份成功”当成原地恢复完成。

## 验证与平台边界

合成目录测试覆盖明确确认、单文件限制、原配置备份可恢复、请求幂等、文件身份替换、归档篡改、候选元数据变化、工作区备份位置变化、未知会话、意图被忽略／审计失败、发布后终态事务失败、重启不重放、未知当前字节拒绝解除，以及 schema 12 升级与迁移前快照。前端测试覆盖选择备份、单独应用确认、读取记录、只读核对和明确解除。

这些测试不等于真实 CDDA 加载／存档验收，也不认证所有平台的文件系统发布语义。下一步应在用户指定的独立实验实例人工验证声音设置与新世界默认组合，并验证原字节回滚；已有世界组合和跨版本迁移继续单独处理。

## 原字节回滚补充

已增加[单文件明确确认回滚](content-config-rollback.md)：从同实例保护归档提取原字节，仅当当前文件仍匹配原应用结果时准备新回滚计划。复用发布与中断保护，schema 14 通过 rollback_of 关联原操作；不是自动回滚或多文件事务。此前“原地回滚未实现”的描述为该切片的历史状态。
