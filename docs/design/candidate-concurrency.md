# 固定 QA 组合的并发候选准入

日期：2026-10-28。状态：实验实现，USR-001 未完成真实双开验收。

## 入口与适用条件

默认构建保留普通方案的全局互斥。显式启用 Cargo feature `candidate-concurrency` 后，macOS arm64 可选择以下两个候选方案；其他平台、未知包、普通方案不会因此获得并发权限：

- `cdda-0h-macos-concurrency-candidate-v1`
- `cdda-0i-1-macos-concurrency-candidate-v1`

桌面实验构建命令为 `npm run desktop -- build --debug --features candidate-concurrency`。界面选择候选后可以请求服务端预览，已有占用不在前端直接禁用此请求；服务端仍拒绝全局未知占用、共享安装、共享实例和文件任务。预览之后仍需明确确认。

候选仅对应 [原生入口验证](../quality/macos-native-entry-verification.md) 中本机已经使用的 H/I 修改版 QA 封装：本体位于 `Contents/MacOS/cataclysm-hub-qa`，固定程序、库、资源、Info.plist 和包内其他静态条目组合。不接受调用方传入摘要白名单、绑定信任位或任意参数。原始官方发行包尚未具备可重复的同等入口准备流程，不能把这两个 QA 组合发布为正式支持范围。

## 静态身份与可变数据

程序复用既有导入摘要、确认摘要与目录身份检查。候选另对完整包的相对路径、条目类型、链接目标、普通文件 SHA-256 形成确定性指纹。记录按路径/类型/值排序，每个 UTF-8 字段后追加 NUL，再求 SHA-256。上限 20000 个静态遍历条目、32 层和 2 GiB 普通文件读取；IO 或预算失败即拒绝。检查在阻塞线程运行。

| 候选 | 固定静态包指纹 |
|---|---|
| H QA | `033a9cdbd5ce0fe2ff040c5fa9c96360b4bb620c796316751db67ac355741b67` |
| I QA | `b09651201f62aeede5798347ec2c7e7a3dd55ebd6935033afda581a7c4453982` |

仅排除两个已知生成缓存树 `Contents/Resources/cache` 和 `Contents/Resources/data/cache`，它们存在时必须是普通目录；这些树仍参加完整安装范围的链接/硬链接/特殊文件检查与写入占用。实例存档、配置、日志和运行环境不纳入静态指纹。修改缓存内容或文件时间不使静态身份失效；修改程序、资源、库、plist 或增加其他静态条目会被拒绝。

候选直接运行已核验本体，清空继承环境，只使用预览列出的环境：独立 HOME/临时/XDG 目录、CFFIXED_USER_HOME、包内动态库路径及固定 PATH。不是系统沙箱，不承诺阻止外部进程或另一工作区修改这些目录。

## 准入与生命周期

沿用 mutation 门、持久 session 和原有 SQL 占用投影，没有新增租约表或数据库信任字段。确认时再次核对候选指纹、程序和目录身份，比较完整安装包与完整实例根两个写入范围，在同一临界区持久记录 starting 和审计之后才 spawn。

只有本次 Hub 实际启动、成功持久记录 running、仍由它等待退出的候选会话，才在占用投影上省略该会话的全局声明。内存记录固定两个目录的物理身份；必须有完整的两个目录写入声明、running 状态及相同目录身份，否则保留原全局保护。记录不是可恢复租约，不是可由前端设置的信任状态。目录声明本身始终保留。

- 两个独立候选可同时运行；同安装包、同实例及物理重叠仍冲突。
- 普通启动与其他文件任务保留全局准入；实例备份允许在来源和备份目录均独立时与已有候选会话并行，见下文备份切片。
- 正常直接进程退出后，仅释放该会话；不证明游戏保存成功或世界语义一致。
- 候选非零/信号退出、wait 失败记为 interrupted_unknown，需按既有流程核实关闭。
- 收到退出结果后，先立即撤销内存资格（不等待其他请求释放 mutation 门），再在 mutation 门内写终态。终态事务失败时，残留 starting/running 意图因此恢复全局保护，另一会话仍保留自身占用。
- running 记录失败不会授予范围资格，仍监测已启动的子进程。
- Hub 重启不恢复内存资格；旧活动会话由既有逻辑标为 interrupted_unknown，继续全局保护。

候选不支持包装器或子进程接管。生产包固定本体与参数；合成 shell 仅存在于 `cfg(test)` 测试夹具，不存在于可交付构建的候选白名单中。

## 验证边界与下一步

自动回归覆盖独立同时确认、重复确认、共享安装、A 退出不释放 B、静态资源确认前变化、starting/running/终态记录失败、异常退出、重启未知和活动根替换。前端覆盖显式选择候选后才向后端请求准入。`binding_verified` / `save_binding_verified` 不提升；只读冲突报告仍不授予游戏资格。

本机包可通过忽略测试做只读复验：设置 `HUB_CANDIDATE_QA_ROOT` 为含 H.app 和 Game.app 的专用 QA 目录，运行 `cargo test -p hub-core --features candidate-concurrency --lib local_qa_packages_match_pinned_candidates -- --ignored`。它生成预览但不启动游戏、不写入包或玩家目录。

下一步在实验构建中完成 Hub H/I 真实双开、交替/近同时保存、各自跨进程重载和 A 退出后 B 继续游玩；之后接入按实际源/目标判断的文件任务协调。进程存在或固定指纹通过都不能替代这些验收。


本轮实际验证：本机 H/I 两份 QA 包的上述只读预览测试通过，合计 74.91 秒。此耗时包含完整包安全检查与静态内容读取，是当前实验入口的性能限制；尚未针对该入口启动真实游戏，不能据此认定双开、退出或存档语义已通过。


交付检查：启用实验特性的工作区 Rust 测试 195 项通过（本机包只读用例作为显式忽略测试另行执行并通过）；前端 56 项通过，类型检查、Clippy、格式检查和实验特性 macOS debug `.app` 打包通过。未将合成子进程测试记作真实游戏并发验收。
