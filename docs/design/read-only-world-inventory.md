# 只读世界候选扫描实现说明

日期：2026-10-27 · 实现版本：opaque-directory-v1 · 状态：开发预览。

## 范围与证据

本实现对工作区中已明确登记的存档根目录进行目录枚举；不在设备其他位置搜索，不读取角色或地图内容。每个顶层普通子目录是一个世界候选，identity_confidence 固定 unknown、boundary_verified 固定 false。角色身份与世界语义尚未识别，`.sav` 等名称不会被当作可靠关联证据。

这是 WORLD-001/002/004/005/006/007 的基础支撑，尚不等同于 AC-002 的目标版本适配验证。只有版本化适配器及已授权样本通过后，才允许将候选提升为已确认世界范围。

## 枚举语义

返回相对路径、文件类型、普通文件大小和候选范围。顶层普通文件、链接及其他特殊条目放入共享/未归属集合；目录和空目录均保留。符号链接列为 symlink，记录 LINK_NOT_FOLLOWED，不检查链接指向内容；其他特殊文件记录 UNSUPPORTED_FILE_TYPE。

使用打开的目录能力句柄访问子项，避免拼接绝对路径后在环境权限下重新递归。已观测的链接不跟随；目录能力限制相对路径访问范围，仍不把并发变化的目录视作稳定快照。库边界参见 [cap-std Dir 文档](https://docs.rs/cap-std/4.0.3/cap_std/fs/struct.Dir.html)。

最多枚举 20,000 条目、递归 32 层。条目不可读、名称含无法无损表示的字节/控制字符/反斜杠、超过限制时记录具体问题且 enumeration_complete=false。当前不提供按页继续枚举；UI 分页只是已获取清单的展示分页。链接警告不令目录枚举本身不完整，但链接载荷仍不具备备份支持资格。

文件大小和总量以十进制字符串传输，不经 JS 整数表示原始精确值。候选统计通过一次分组累加建立，不为每个目录反复扫描全清单。结果排序仅保证已收集数据的稳定显示；达到枚举上限时不承诺每次截断子集相同。

## 任务、取消与互斥

start_world_scan 接收 UUID request_key，同键重放返回持久 task；配置当前不可变，因此同键不可能改变扫描根目录。请求接受后事务记录 running 意图及审计，后台线程枚举，每 150ms 尝试持久进度，revision 单调增加。

cancel_world_scan 返回取消请求状态；任务到下一个条目/目录边界停止，只有工作线程结束并记录终态后才是 cancelled。取消与结果发布通过 mutation 锁串行化，取消任务不会发布成功报告或覆盖旧报告。取消不能中断当前阻塞的操作系统目录调用，脱机/网络盘的响应时限仍需平台验证。

当前采用整个工作区的保守任务互斥：扫描期间拒绝管理器启动，存在运行中或未知会话时拒绝新扫描。同一时间只接受一个活动扫描。它不是后续覆盖恢复所需的通用多资源锁，外部进程也不受此锁约束。

重启将遗留 running/cancelling 任务标记 recovery_required / TASK_INTERRUPTED，保留原意图，不盲目继续或发布部分结果。扫描是只读操作，用户可用新请求重新扫描；旧任务和审计不会被删除。

## 持久化与迁移

schema 2 增加 task 与 world_candidate。成功结果的序列化报告、任务状态、候选 ID 更新和审计在同一 SQLite 事务提交。每个候选 ID 以 workspace_id + relative_root 持续关联；这是位置候选身份，不保证目录更名/复用后仍是同一个游戏世界。旧候选记录保留，但 UI 仅展示选定报告中的条目。

schema 1 升级前使用 VACUUM INTO 创建独立元数据副本，重新只读打开做 quick_check 并同步备份文件，再事务执行 migration-002.sql。迁移失败保留旧 schema 和备份。备份机制遵循 [SQLite VACUUM INTO 语义](https://www.sqlite.org/lang_vacuum.html#vacuuminto)，而非直接复制可能带活动日志的数据库文件。此实现尚不宣称通过断电持久化验证，也不提供自动 schema 降级。

## 已知限制和后续

扫描报告不包含内容哈希、冻结副本、游戏一致性或兼容结论。缺少真实版本规则时，无法判断一个世界是否跨多个目录、哪些根目录文件为共享依赖，也无法建立角色关联。任何报告都不能直接绕过边界确认成为“完整世界备份”输入。

下一步需要版本/布局 fixture、边界计划和人工确认，再引入有界复制、源变化检测及独立完整备份。Windows/Linux 的原生扫描、大小写/挂载点行为仍按平台矩阵验证；非 UTF-8 文件名的实际文件系统测试仅在允许此类名称的 Linux 环境执行。
