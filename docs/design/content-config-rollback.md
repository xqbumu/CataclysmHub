# 配置单文件原字节回滚

日期：2026-10-29。状态：已实现明确确认的单文件回滚，未执行真实游戏验收。

## 适用记录

仅接受原始配置应用记录，且状态为 `applied` 或用户已核对确认保留应用结果的 `resolved_proposed`。未完成记录须先完成只读核对；不能直接回滚仍处于保护状态的操作，也不提供回滚的反向重做。当前文件必须与原操作的应用后 SHA-256 一致；已有后续编辑则拒绝，既不会合并字段，也不会覆盖第三种内容。

用户从配置应用历史点击预览，后端校验所有 Hub 会话／文件任务已经结束、实例安装身份、当前工作区与同实例保护归档。现有跨进程外部写入限制仍适用：身份、摘要检查和 rename 不是跨进程 compare-and-swap，须先停止外部写入者。

## 字节来源与边界

复用既有完整归档解析器，新增有界单文件捕获，只允许 `config/options.json` 或 `config/user-default-mods.json`，捕获最多 1 MiB。仍验证整个归档的格式、条目、摘要、结束帧及校验期间变化；不是找到目标成员就提前返回，也不向磁盘解压整个实例。

捕获内容须与原操作的变更前摘要相等。原配置为有效 UTF-8 JSON，回滚保留其原始字节、空白、换行和字段顺序，不经 JSON 重序列化。权限沿用回滚时目标文件的普通权限，不承诺恢复原 ACL、扩展属性或全部元数据。

## 发布与记录

复用既有短期计划、单文件临时发布、原文件身份／摘要复核、归档与候选元数据复查、确认及幂等请求机制。计划的 before 为当前已应用字节，after 为保护归档中的原字节。执行时归档必须包含 after，而不是回滚前的 before；普通应用仍验证归档中的 before。元数据变化会使计划失效，回滚不认证恢复后资源加载或存档兼容。

schema 14 给 `config_change` 增加可空 `rollback_of`，关联原操作。回滚生成新的操作记录，原操作记录保持历史事实；现有 `config.apply` 审计动作记录单文件发布，历史通过 `rollback_of` 明确回滚来源。迁移前保存 metadata-v13 快照；旧记录该字段为 NULL。

只有用户核对目标、关联操作、备份及前后摘要后单独确认才写入。重复请求返回已有回滚记录，不重放。之后再次对原记录发起回滚会因当前字节不再匹配原应用结果而拒绝。只修改一个配置文件，不修改角色、物品、地图或已有世界 mods.json。

## 中断核对

回滚中断或结果事务失败沿用 `applying`／`recovery_required` 全局保护，重启不重放。对回滚记录而言：

- `original` 表示文件仍是本次回滚前的已应用版本；
- `proposed` 表示文件已是保护备份中的原字节；
- `other` 表示两者均不匹配，不允许直接解除保护。

用户可只读核对后明确保留当前版本并解除该记录的保护。解除不再次写文件，不宣称原回滚操作成功。临时文件与跨平台持久化限制继承[单文件应用契约](content-config-application.md)。

## 验证

回归覆盖完整原字节恢复、预览只读、明确确认、关联记录、重复请求、重复回滚拒绝、后续编辑拒绝、归档篡改拒绝、回滚终态审计失败后只读核对，以及 schema 13 升级保留历史。原有单文件应用重启不重放、审计故障和目录保护测试共同覆盖共享发布路径。界面验证预览不写入、独立确认、不向未完成或回滚记录提供回滚按钮，以及中断核对方向提示。
