# 备份名称、备注与本机保留标记

日期：2026-10-28。状态：WP-11 的标注基础切片已实现；保留策略计算、清理预览、最后有效副本保护和删除执行尚未开放。依据 BACKUP-009/010/011 及备份保留设计，不将本切片视为整个 WP-11 完成。

## 用户行为与边界

备份卡可编辑名称、备注和保留锁。名称非空时作为卡片标题，同时保留原创建时间；备注按原换行展示。保留锁和命名标记分别呈现，单独备注不等于命名保留标记。留空名称恢复为创建时间标题，可主动清空备注或解除锁标记。

这些信息仅存入本机 SQLite，不改动 archive.tar.zst、receipt.json、内部 manifest、UUID 目录名、原验证时间或摘要。独立校验/恢复保持无需原 DB；移动备份到另一台机器不会自动携带本机标注，丢失元数据也不会令原始归档无法恢复。元数据副本会包含名称和备注。

目前没有任何清理/删除入口。保留锁是管理器元数据标记，不能阻止操作系统或其他程序移动/删除文件，不能解释为文件加密、权限锁或不可变属性。后续保留集合必须包含命名/锁定备份，并独立保护最后有效备份；不能仅靠前端标记实现删除安全。

## 数据与事务

schema 6 给 backup_archive 追加：

| 字段 | 默认值 | 含义 |
|---|---|---|
| display_name | 空字符串 | 用户名称，去除首尾空白，最多 128 个 Unicode 标量 |
| notes | 空字符串 | 最多 4000 个 Unicode 标量，保留换行和制表符 |
| retention_locked | false | 本机保留锁标记，SQL CHECK 限定布尔值 |
| metadata_revision | 0 | 乐观修订号，范围 0～9007199254740991，保持 JS number 精确 |
| metadata_updated_at | null | 实际修改的 UTC RFC3339 时间 |

名称拒绝包括首尾在内的控制字符；备注除 LF/TAB 外拒绝控制字符。前端计数与 Rust Unicode 标量计数一致，后端仍执行全部输入校验。新建备份使用显式列名插入原不可变字段，新标注依赖默认值。

update_backup_details 只执行本地短事务，在现有 mutation 门内读取记录、检查预期修订号、更新允许字段并写审计。相同规范化内容重复提交返回现记录，不推进版本或重复审计，允许处理首次保存响应丢失。内容不同且修订号陈旧则 BACKUP_DETAILS_CONFLICT；不允许旧草稿覆盖新名称或解除较新锁定。修订号达到安全整数上限后拒绝递增。

修改名称/备注产生 backup.details_update；锁定与解锁分别产生 backup.retention_lock / backup.retention_unlock。同一次同时修改信息与锁时，两条审计和字段更新在同一事务中。日志只记录操作类型、备份标识、结果与时间，不复制名称/备注正文。审计失败则所有字段及已插入的审计共同回滚。

这是同步元数据修改，不创建长时间文件任务，不需要介质在线，也不因已有游戏或文件任务而拒绝编辑；仅与任务开始/终态等短临界区串行化。编辑成功不代表介质在线或重新完成了归档验证。

schema 1～5 升级前保存、校验并同步元数据副本，再事务执行迁移。迁移中后续 ALTER 失败时，之前的 ALTER 也回滚，保留旧版本、原数据与副本。

## 桌面并发编辑

打开弹窗捕获当前 metadata_revision。轮询更新不会替换未保存草稿；发现记录变更后提示旧草稿保存会被拒绝，并提供用户主动载入最新信息替换草稿的入口。取消不产生写入，保存错误保留草稿。名称、备注、创建时间及锁定状态始终是原备份的标注，不生成另一个归档。
