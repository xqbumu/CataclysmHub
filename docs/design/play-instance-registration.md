# 游玩实例登记：USR-001 第一阶段

日期：2026-10-28。状态：本文记录第一阶段登记基础。后续已增加[受全局保护的实例参数试运行](instance-launch-trial.md)，完整绑定与并发仍未实现。

## 行为

游戏安装与游玩实例分离。一个安装可登记多个实例，不同安装可各自登记实例；实例记录安装 ID、登记时可执行文件 SHA-256、名称及规范化数据根目录。服务端固定绑定状态为 `unverified`，调用者不能提交“已验证”。该目录是未来存档、配置、缓存、日志的整体隔离范围，尚未确认具体游戏目录布局。

只接受用户通过本机目录选择器选择的现有空目录。检查与所有已导入安装工作目录、工作区三目录、应用元数据目录、所有已登记实例范围分离。目录身份及祖先身份比较覆盖链接别名和大小写不敏感文件系统；已有范围不可访问时保守拒绝。后续导入安装也检查实例范围，防止反向重叠。名称 1～100 个可显示字符，最多 200 个实例。

登记前重新计算程序摘要；程序变化拒绝。登记不写探测文件，不创建/迁移存档，不启动程序。重复相同目录、安装、名称与摘要返回原记录，无重复审计；同目录不同登记内容拒绝，嵌套目录拒绝。实例与不含名称/路径的审计一起提交，任一失败整体回滚。

## 持久化与接口

schema 7 新增 `play_instance`，安装外键禁止悬空，数据目录唯一，绑定状态 CHECK 限定 `unverified`。旧库先生成经校验的 SQLite 副本，再事务迁移；迁移失败保留旧版本。输入和输出类型由 Rust 生成 TypeScript。

- `register_play_instance({input: {installation_id, name, data_root}})`：目录必须持有当前进程原生选择授权。
- `get_dashboard` 新增 `play_instances`，包含全部已登记实例；直接核心 API `play_instances()` 用于读取。
- 主要拒绝：`NAME_INVALID`、`SOURCE_CHANGED`、`INSTANCE_SCOPE_OVERLAP`、`INSTANCE_ROOT_NOT_EMPTY`、`INSTANCE_ROOT_IN_USE`、`INSTANCE_LIMIT`。目录不可访问返回 `PATH_INVALID`；事务失败返回 `DATABASE_ERROR`。

## 安全边界与下一阶段

这只是登记时的目录检查，不是持续目录租约、可写性保证或游戏隔离证明。外部改名、挂载变化、文件写入均可能使登记失效；将来实际启动必须重新打开并核对真实身份和完整写入范围。登记中观察到空目录不能作为将来启动授权。

第一阶段交付时：现有通用启动仍使用原工作目录与原参数，不使用实例目录。全局会话与任务互斥保持，未知/中断会话保持保守限制；备份仍针对原工作区存档根目录。没有提供实例启动按钮、并发执行或每实例备份。

下一阶段需要针对明确游戏版本取得真实参数及目录行为证据，建立覆盖存档/配置/缓存/日志/安装写入的适配器，拒绝覆盖受控路径的自定义参数，然后实现按实例会话、真实目录资源租约、未知会话恢复与冲突判定。只有这些验证完成后，才满足 USR-001 的双版本同时游玩验收。
