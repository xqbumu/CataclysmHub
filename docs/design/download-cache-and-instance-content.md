# 下载缓存、受限解压与实例资源配置

日期：2026-10-29。范围：游戏发行附件、模组与声音包共用下载层；资源配置始终绑定实例及关联安装。

## 生命周期

来源目录首次同步后只由用户手动更新。来源目录、下载缓存、解压结果、资源来源登记、实例可发现资源和配置引用分别记录，不能将前一步的成功显示为后一步成功。

| 阶段 | 行为 | 当前边界 |
|---|---|---|
| 选择发行附件 | 显示宿主 OS/CPU，按文件名提示匹配或其他平台 | 不猜测未知平台，不自动选择/执行；不认证兼容性 |
| 下载或复用 | 相同来源、仓库、标签、附件 ID、URL、名称先查缓存 | 缺失、大小或摘要不符才重新下载；不同发行身份不会仅凭文件名合并 |
| 缓存核验 | 通过 UUID 容器和文件名打开普通文件，重算 SHA-256、核对长度和当前上游摘要 | 不信任回执显示路径，不跟随文件/目录链接；没有上游摘要时只证明与本地原回执一致 |
| 解压 | 用户单独确认；重新核验缓存，独立暂存目录完成后发布并记录 | 不覆盖游戏或实例，不自动导入或启用；每次显式解压生成独立目录 |
| 资源登记 | 单包目录直接含 modinfo.json 或 soundpack.txt，沿用资源来源库 | 合集不是单个模组，不自动全选；登记不等于游戏可发现 |
| 实例配置 | 安装 → 实例 → 本次发现资源 → 有序模组或声音选择 → 后端预览 → 保护副本 → 确认应用/回滚 | 沿用既有单文件保护流程；已有世界组合只读，跨版本迁移另行处理 |

## 缓存复用及恢复

下载、同步、解压通过现有 Store 锁串行，不增加队列或数据库表。两个同时请求不会产生并行重复传输，后到请求提示繁忙，重试会再次检查成功缓存。成功回执持久化后，重启仍可离线复用。旧回执缺少身份字段时不冒险复用。

原始下载继续保存于系统托管 downloads/{download_uuid}/。新下载使用 partial，长度和摘要核对后发布；损坏缓存保留，不覆盖或自动删除。成功缓存复用不重新发起附件 HTTP 请求。没有提供跨不同资产身份的内容寻址去重、断点续传、自动容量淘汰或更新轮询。用户确认删除原包时保留解压目录及其独立记录；解压记录是完成时事实，不持续证明目录未被修改。

## 解压约束

使用 Rust zip、tar、flate2 读取归档，不调用归档中的程序。支持普通 ZIP 的存储/Deflate、普通 TAR、TAR.GZ/TGZ；每个输出是新目录，拒绝绝对路径、父目录穿越、Windows 保留名称、反斜杠/盘符、重复路径及大小写目录冲突。只写普通文件和目录；拒绝链接、特殊文件、TAR 扩展记录，不恢复所有者、setuid 或扩展属性。DMG、7z、带链接的应用包和其他不支持格式需使用系统工具核对处理，不解引用链接以伪造应用包。

ZIP 在建立索引前逐条预检中央目录（最多 32 MiB），拒绝 ZIP64 中央目录、分卷和歧义结束记录；普通 ZIP 最多 65534 项。总体最多 100000 个条目、32 层目录、单文件 2 GiB、总普通文件 8 GiB；归档路径最长 2048 字节。逐文件长度核对；ZIP 解码同时检查其读取错误。普通文件保留可用的修改时间，Unix 执行权限收敛到 755/644，避免带暖缓存副本仅因复制改动 mtime。此行为不保留代码签名的扩展属性，也不代表 macOS 完整发行包认证。

失败尽力清理本轮新建 partial，原归档保留，成功目录不发布。强制退出或落盘失败可能留下 partial 或未登记的新目录，没有自动重放或递归清理用户目录。解压完成后再次核验归档，再发布；这不是对外部进程写入的系统沙箱。空闲磁盘不足会返回 I/O 错误；当前没有下载/解压磁盘空间预留机制。

[ZIP 官方库文档](https://docs.rs/zip/latest/zip/)、[TAR 官方库文档](https://docs.rs/tar/latest/tar/)。实现并未使用库的无条件覆盖解压接口，而是逐条目检查和独占创建文件。

## 实例配置交互

模组候选按名称展示，并显示 ID、来源路径、版本和依赖声明；已选列表支持添加、移除、上移和下移。重复 ID 候选不能直接选入，不擅自选择覆盖赢家；保留手工 ID 编辑用于排障。每次编辑清空旧比较和后端预览，防止旧草稿继续用于保护/应用。

声音包从当前实例/关联安装的发现结果选择，保留 ID 输入和声音开关。更换声音包需重启并在游戏内验证播放。模组默认组合只影响后续新世界；已有世界 mods.json 不随此操作改变。候选来自扫描范围，不根据版本字符串自动宣称兼容；后端继续检查重复 ID、缺失依赖、读取变化、保护归档和活动会话。

后续已补齐 [来源库到指定实例的受控部署](instance-content-deployment.md)：macOS/Linux 实现通过现有任务将完整资源发布到实例 mods/sound 新目录。普通“独立资源库副本”仍不等于实例部署；部署后也需重新读取配置。Windows 发布、已有世界增删模组、安装级共享写入及真实加载/播放验收仍未完成。

## 验证

回归覆盖游戏/模组/声音缓存重启离线复用、回执路径不受信任、大小/字节/摘要/链接拒绝、解压失败不发布、成功结果独立落盘及删除原包保留结果、ZIP 路径和大小写冲突、TAR 时间戳/执行位及链接拒绝。前端覆盖宿主提示、复用入口、解压确认，以及按实例资源选择、模组顺序和编辑失效。

本轮没有运行真实游戏、播放声音或执行归档中的软件。三平台路径规则经过本机测试，Windows/Linux 运行验收仍需独立完成。

显式联网声音包验收已通过：CC-Sounds-sfx-only.zip，11141644 字节，上游摘要匹配；第二次请求复用同一回执，解压 797 项、11739788 字节。见 [归档结果](../quality/evidence/download-cache-2026-10-29/live-sound.json)。该实验未执行或播放包内内容。

缓存核验与网络传输共用取消生命周期，缓存每 64 KiB 读取检查取消；取消后不进入网络回退。流式写盘、哈希和刷盘在受控 blocking worker 中执行，每块等待完成，避免取消时丢弃仍在写盘的任务。详见 [审查修复记录](../quality/review-remediation-2026-10-29.md)。
