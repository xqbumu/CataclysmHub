# 平台目录、Hub 配置与实例操作改进

日期：2026-10-29。依据：[平台目录调研](../research/platform-directories-2026-10-29.md)、[CDDA 与相关启动器调研](../research/content-instance-management-2026-10-29.md)。先核对官方规范和上游源码，再实施本轮改动。

## 对应用户反馈

| 反馈 | 实现 |
|---|---|
| 设置页选择按钮不齐 | 目录行采用图标 / 可收缩输入 / 固定 84px 按钮三列；输入与按钮同为 40px 高 |
| 工作目录遵循系统约定 | 通过 Tauri app_local_data_dir 解析推荐根，新工作区提供推荐 saves / backups / content；新实例默认在 instances 下创建唯一独立目录 |
| 重置前备份配置 | 新增持久化的每实例启动偏好与版本号；预览、确认、创建 JSON 备份后再事务重置并审计 |
| 控件大小不一致 | 单行 Input/Select 统一 40px 高、14px 字号、8px 圆角和内边距；复选框及多行输入保留语义尺寸 |
| 资源缺少目标约束 | 内容页分“实例配置”与“资源来源库”；目标必须先选安装再选该安装的实例，读取／配置固定到实例 ID |
| 实例启动配置不直观 | 实例卡主按钮“启动”、次按钮“配置”；启动方案在该实例专属窗口选择、保存、预览和确认；冲突诊断按需展开 |

## 默认目录与已有数据

长期数据不进入 cache/temp。推荐根为 app_local_data_dir 的同级独立应用命名空间，避免与当前元数据根嵌套：

| 平台 | 示例（以系统 API 实际返回为准） |
|---|---|
| macOS | ~/Library/Application Support/com.cataclysmhub.desktop.workspace |
| Windows | %LOCALAPPDATA%/com.cataclysmhub.desktop.workspace |
| Linux | $XDG_DATA_HOME/com.cataclysmhub.desktop.workspace，未设置时通常位于 ~/.local/share |

根下为 saves、backups、content、instances。目录预览只读，保存工作区时创建实际使用的推荐目录；选择自定义路径仍需本机选择器授权。创建实例时由后端在实例父目录下分配唯一子目录，先检查资源占用及受保护范围，不能在其他实例或安装内创建。拒绝托管入口的外部符号链接。创建失败可能保留已经创建的空目录，不为清理而删除未知内容。

现有工作区不自动迁移，元数据位置不变。Windows 既有 app_data_dir 元数据位置也不在本轮迁移。Debug 设置 CATACLYSM_HUB_DATA_DIR 时，推荐根跟随该隔离路径并使用同级 .workspace 命名空间；不会落入真实用户默认数据区。备份允许用户改选外置目录；同盘默认目录不是异盘灾备保证。

## “只重置配置”的准确范围

本轮可重置的持久 Hub 偏好是每个实例的启动方案，默认值为“未选择”。同时清空界面筛选状态。已有工作区、安装、实例、资源来源、备份、任务、应用/回滚历史和恢复保护属于业务记录，全部保留。游戏 options.json、世界 mods.json 等也不在此重置范围。

不能把旧 workspace 的 backup_dir 直接写成新默认值：既有归档通过旧 workspace 定位，覆盖后会失联。路径迁移必须另行设计，不能伪装成偏好重置。

schema 15 新增 hub_preferences；旧数据库升级前继续创建并核验元数据快照。保存启动方案验证实例存在、方案受当前平台与构建支持，但不授予兼容或绑定可信标记。

重置流程：

1. 读取偏好及 revision，展示范围并要求确认。
2. 后端在 mutation 门内复查 revision，拒绝过期预览。
3. 在元数据目录的 config-backups 中用独占创建方式写入新的 JSON 文件，包含旧偏好和只作参考的工作区路径；同步文件，Unix 还同步目录。
4. 成功后事务清空启动方案、递增 revision 并写审计。备份失败不执行重置；事务失败保留旧配置和已完成备份。
5. 返回备份路径。没有自动导入备份入口，不删除旧 JSON。

## 实例与资源约束

- 共享来源库只负责本地包登记及独立副本，不把登记、发现、配置声明、实际加载混为一谈。
- 目标实例仅能从所选安装的关联实例中选择；切换安装、实例、程序摘要或实例路径时清空报告，忽略迟到响应。报告身份不匹配则拒绝显示为当前配置。
- 模组 version 字段不提供通用游戏兼容约束，因此不增加假定的 semver 判定。有效候选仍来自目标安装与实例的实际发现，写入沿用后端摘要、资源、占用和保护备份复查。
- 新世界默认模组与已有世界模组独立；已有世界仍只读观察。声音设置对所选实例生效，实际声音需重启游戏后另验。
- 启动方案按实例 ID 保存。打开另一实例时重新读取其偏好、清除确认；启动仍需服务端计划和最终确认，不把保存偏好当作启动授权。

## 日常启动简化（2026-10-29）

已保存普通方案的实例，点击“启动”后读取当前偏好、重新创建后端计划，再调用原启动接口；不复用旧计划，不重复打开设置和确认窗口。后端原有摘要、过期、会话及资源检查保持执行，任一步失败不继续启动。实验并发方案继续经过明确的设置与确认。

实例卡增加独立“启动设置”入口。首次设置主界面提供已适配的 CDDA H / I macOS 版本选择；旧版和实验选项放入高级设置。首次最终确认显示实例与存档，环境变量、参数及摘要折叠为技术详情。首次启动成功后保存该实例方案；保存失败明确提示，不将已经启动的游戏报告成未启动。

没有按显示名称推断版本，也没有执行未知程序来探测版本；未知版本及其他变体仍需进一步建立可信适配证据。这一限制不能通过自动套用 H/I 参数消除。

本轮为前端交互调整，新增回归验证已配置实例通过新计划直接启动、后端检查失败不启动，并保留首次确认及 A/B 实例设置隔离回归；未操作真实游戏。

## 版本识别与首次推荐（2026-10-29）

首次打开实例启动设置时，按关联安装 ID 读取程序并重算 SHA-256；与登记摘要不同则拒绝识别。匹配已记录的 CDDA H / I 发布样本时报告版本，结合当前 macOS 的 .app/Contents/MacOS 或 Resources 入口推荐已有普通方案。样本摘要及版本自报告依据见 [真实游戏验收契约](../research/cdda-real-game-acceptance-contract.md)。不执行程序，不信任名称或 Info.plist 的通用版本字段。

前端同时核对识别报告的安装 ID 与实例登记摘要。仅在该实例尚无保存偏好时预填推荐方案，首次仍需预览及明确启动确认；保存方案不被自动覆盖。识别失败或未知样本保留手动入口，后端启动保护继续执行。本轮未扩大已验证样本、其他变体或并发认证范围，也不回填安装表的 version / branch 字段。

## 直接导入 macOS 应用（2026-10-29）

导入入口接受本机选择器授权的 .app 目录，仅读取 Contents/MacOS 与 Contents/Resources 下固定的 cataclysm-tiles、cataclysm 及 MacOS 下 cataclysm-hub-qa 候选；唯一候选才登记真实程序路径。普通目录、多个候选、缺失候选、应用内链接或不可执行文件拒绝。不会使用 Cataclysm.sh 或 Info.plist 猜选入口，不执行程序。直接选择普通可执行文件的原流程保留。

实际登记、去重、摘要与安装/实例重叠检查继续以解析后的程序为准。合成回归覆盖唯一入口、多个入口、启动脚本、普通目录、子目录链接，以及应用导入后直接程序导入去重。此功能不扩大变体适配；不识别上述约定名称的应用可手动选择。未完成原生选择器的人工验收。

## 识别说明统一（2026-10-29）

安装卡改为“登记版本”。新安装的程序摘要若匹配已记录样本，在登记中保存样本版本与 DDA 分支；既有 version/branch 都为空的记录在 Dashboard 返回时按登记摘要补充显示，不修改旧数据库行，不覆盖已有明确版本/分支，不扫描名称或侧车。这描述登记的程序内容，不能作为磁盘当前内容的复查结果；启动与只读识别仍重算当前程序摘要。

导入成功提示不再固定写 unknown。首次确认说明不再否认前一步的样本识别，而是明确版本样本识别与目录绑定、资源兼容性验收分别记录。原启动计划及资源保护流程保持原样。

打开已有启动设置时，若当前程序重新识别出的推荐方案与已保存方案相同，可直接进入预览，无需在高级选项重复勾选。推荐不同、未知样本或实验方案仍保留原有明确选择要求；不会因匹配而自动启动。
