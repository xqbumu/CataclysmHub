# 独立备份、恢复与保留策略详细设计

版本：0.1.0 · 日期：2026-10-27 · 状态：待评审 · 责任角色：备份引擎负责人。需求：BACKUP-001～011、AC-006～010、PRD §8/10/17。

## 完整备份封装

建议采用一个可搬移目录作为备份单元：`{backup_id}/archive.tar.zst` 与 `receipt.json`。归档内部仅允许一个 `manifest.json` 及 `data/` 下的载荷。清单记录每个目录和普通文件；空目录也保留。首版遇到软链接、硬链接语义、设备、FIFO、socket 等不支持类型必须失败并列出，不能静默跳过后声称完整。

`manifest.json` 保存格式版本、源范围、世界和角色证据、游戏/平台/档案信息、consistency、工具版本、文件清单、总数量和字节数。单文件 SHA-256 针对原始字节。目录无文件哈希。清单本身不列为载荷文件。

归档摘要不能放在参与该摘要计算的归档内部，否则产生自引用。外置 receipt 保存归档 SHA-256、清单原始 UTF-8 字节 SHA-256、验证时间与结果；内部 manifest 不包含自身/归档摘要及事后验证结果。这是对 PRD §10.3 的封装细化，见 [ADR-0003](../adr/0003-backup-envelope.md)。

receipt 丢失时仍可通过内部清单逐文件验证后导入，来源信任标记为 unknown；应用可重新生成本地 receipt。哈希证明字节一致，不能证明发布者真实性；恶意方可同时改写载荷和清单，仍须执行解包安全检查。

## 创建与发布

使用 [一致性流程](consistency-and-tasks.md) 的冻结副本。预检源/目标不重叠、备份卷身份、权限、空间及限制。空间估算按最坏无压缩载荷、staging、保护备份和额外余量计算；压缩率不能作为足够空间的保证。空间可能并发消耗，写入错误仍须安全处理。

在备份目标卷的 `.partial-{task_id}` 目录写归档与 receipt；完全解码验证清单集合、大小、哈希及无额外条目后，关闭并同步文件，重命名目录为最终 backup_id，再补记数据库。最终命名冲突即失败，不能覆盖既有备份。平台不支持可靠发布语义时保留 unpublished 状态，兼容矩阵中记录限制。外置盘断开后不把缓存验证状态当作当前可读性。

## 恢复协议

| 步骤 | 前置/操作 | 失败行为 |
|---|---|---|
| 计划 | 验证来源、范围、目标真实身份、版本资源差异；计算新增/替换/移除 | 不改动目标 |
| 确认 | 展示具体目标、差异、保护策略；确认绑定 plan_id 和摘要 | 过期或内容变化需新计划 |
| 锁定与复检 | 获得根/世界冲突锁，禁止管理器启动相关游戏；重扫目标 | 目标变化则 PLAN_STALE |
| 保护 | 非空目标生成完整、已验证的保护备份 | 保护失败中止覆盖 |
| 隔离解包 | 在目标同卷、目标外的 staging 解包并逐项验证 | 仅清理归属明确临时数据 |
| 受控切换 | journal 记录意图；target → rollback；staging → target | 按 journal 恢复原目录 |
| 后验 | 再次遍历新目标，严格集合、类型、大小、哈希相等 | 回滚；回滚失败保留所有副本并阻止启动 |
| 完成 | 写审计、更新索引、保留保护备份及回滚记录 | DB 失败以 journal 对账，不删除数据 |

两个重命名不是一个原子操作，旧目标移开后存在短暂空窗。只有经过故障注入验证的本地文件系统进入覆盖恢复支持矩阵；网络文件系统和无法可靠识别卷的路径首版仅支持恢复到新空目录。跨卷输入先复制到目标同卷 staging，不能跨卷 rename 假装原子。

覆盖恢复精确替换计划范围，因此当前多余文件也会被移出；必须在预览中列出。整个存档根目录恢复与所有子世界互斥，不能把它拆成独立世界操作而失去整体恢复语义。空目录恢复可省略保护备份，但须复检仍为空且未被其他进程写入。

## 解包安全与格式语义

只接受相对路径，禁止空段、`.`、`..`、绝对路径、驱动器、UNC、反斜杠、NUL、重复路径、文件与目录前缀冲突；以目标平台规则检查大小写、Unicode 规范化、Windows 保留名和尾部点/空格等碰撞。检查 TAR 扩展头的最终有效路径，不能仅检查原始头字段。打开文件时防止父路径被替换为链接；禁止跟随归档链接和目标已有链接。

限制展开字节数、条目数、单文件大小、路径深度、压缩比、解析深度和处理时间；阈值可配置但须后端上限，默认值通过基准数据校准。超限返回受控错误，禁止自动提高限制。清单声明值与实际流量分别计数。

首版保留原始文件字节和空目录；mtime 可保留但不作为真实性依据。不承诺 ACL、xattr、稀疏布局或跨平台执行位等元数据完全等价；扫描到这些差异必须预检提示。非 UTF-8 文件名首版阻止生成 v1 可移植归档，不做有损改名。

## 保留与删除

建议默认采用 PRD 的最近 7 个自动备份、14 个每日时间桶、8 个每周时间桶。使用用户配置时区划桶并记录时区；保留集合取各规则并集，再并入命名/锁定、保护备份和每个 scope 最近一个 verified 备份。best_effort 不能替代最后一个 quiescent_checked 恢复点；离线卷或校验失败条目不计入有效保底。

Git 历史不因备份保留规则而自动 prune/rewrite。首次启用策略明确确认适用范围；每轮删除先生成数量、容量、时间和保底影响预览，首发要求显式确认后执行。实际删除前重新计算引用、锁和最后有效备份条件。删除中断逐条记录，不把整个批次虚报成功。

## 独立恢复验收

删除应用数据库和世界 Git 仓库后，仅凭归档与恢复说明，仍可恢复至空目录并验证全部文件。应提供与 GUI 解耦的受限恢复入口或工具，设计为 M3 交付；目前没有该工具，不能向用户提供虚构可运行命令。
