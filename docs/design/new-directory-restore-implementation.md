# 新目录恢复核心与独立工具

状态：WP-10 的首个非覆盖恢复切片已实现。桌面恢复任务、原目录替换与回滚均未开放。源为应用生成的 v1 save_root TAR+Zstandard，目标为用户明确指定的全新容器目录。恢复不打开 SQLite 或 Git，不把目标自动绑定成当前游戏存档。

## 使用与结果

```sh
cargo run -p hub-core --bin restore-backup -- /path/to/backup-id /path/to/new-recovery --confirm-new-directory
```

要求目标的父目录已存在，目标本身不存在。拒绝已有空目录、非空目录、目标链接，以及目标与源备份目录的包含关系。现有目录的子级可以作为新的容器，但绝不把其内容混入已有存档。容器包括：

- `data/`：恢复的原始文件字节和空目录。
- `RESTORE_INCOMPLETE.json`：工作开始后同步写入的未完成标记；失败时保留，若最终同步失败则尽力恢复标记。
- `restore-verification.json`：全部回读验证后写入的结果；成功时移除未完成标记。仅当命令成功退出、无未完成标记且有验证结果时，视为本次恢复完成。

结果记录备份 UUID、归档/清单摘要、文件/条目/字节数、原始一致性等级及验证时间。verified 是文件完整性结论，原 best_effort 不会因恢复自动升级，不表示游戏语义、来源可信或版本兼容。报告只描述生成时的状态，后续人工编辑不会自动更新报告。

## 实现与安全边界

1. 规范化源目录与目标父目录，用能力目录句柄执行后续路径操作，预先拒绝覆盖与重叠。
2. 使用已有读取器完整验证归档，校验外部回执（若存在）、内部清单、精确条目集合、类型、大小、文件哈希及 Zstandard 结束。回执不存在仍能依靠内部清单恢复，不等于认证来源。
3. 检查目标可用空间（清单总量 + 16 MiB 预留），独占创建容器、同步未完成标记与父目录。空间检查不能预防后续耗尽。
4. 共用同一个归档解析器进行二次验证和解包，绑定第一次归档摘要，拒绝中途换包。只创建清单中的目录和普通文件；文件 create_new，路径逐层 nofollow。无通用 tar.unpack，没有权限/链接/特殊设备条目的隐式恢复。
5. 边写入边检查每个载荷哈希并同步文件；归档结束和再次整体摘要检查后，从目标重新枚举并回读所有文件，对照精确路径、类型、大小与 SHA-256。同步子目录到根目录。
6. 同步结果报告，再移除未完成标记并同步容器与父目录。失败不删除部分数据、不自动重新执行；选择另一个新目录重新开始。

目标文件系统不支持名称时直接失败；大小写/Unicode 别名导致 create_new 或目录创建冲突时中止，不静默合并、覆盖或改名。当前是写入期间探测，桌面接入前仍需完善平台名称碰撞预检。只恢复普通文件内容和空目录；不恢复 ACL、扩展属性、原始权限、硬链接、稀疏布局和时间戳。

临时容器在操作期间可见，不宣称目录重命名发布的原子性。最终标记和载荷不能与 SQLite 形成跨介质原子事务；本工具没有 SQLite 依赖。目录同步目前在 Unix 执行，Windows、网络盘、拔盘与真实掉电仍待平台验证。若标记写入/同步也失败，可能只留下空容器或不完整记录，不能仅按目录名称判断成功。操作不防御拥有同等文件系统权限的并发恶意进程；恢复时应关闭外部写入者。

## 验证与后续

回归覆盖未知二进制、无效 JSON、中文/长文件名、空目录、空归档、回执丢失、已有目标、链接目标、路径穿越、归档损坏、大小写碰撞和命令行确认。macOS 上使用先前原生应用创建的 3 文件 / 5 条目 / 55 B 归档执行独立恢复；额外 Python 枚举对比源与恢复目录的精确路径、类型与 SHA-256，全部一致。

桌面后续：原生目标选择、绑定目标与摘要的过期计划、用户确认、持久任务/取消/中断恢复记录、操作审计与恢复结果展示。覆盖恢复另需保护备份、替换 journal、故障注入和回滚证明；本切片不包含这些能力，不标记 WP-10 或 AC-006 全部完成。
